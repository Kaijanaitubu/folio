# 個人DB改修：リンク別情報・収録関係の検討

作成：2026-10-20。更新：2026-10-23。状態：仕様相談・記録のみ。実装、DB変更、配備は行わない。決定と開発側提案を区別する。

## 合意・ユーザー指定

### ページ数

- 既存の作品ページ数は、出所の判定を挟まず現在の主リンクへ移す。
- 他のリンクは、そのリンクから読み取れた場合に追加する。既存値を全リンクへ一括複製しない。
- 再取得でページ数がない場合は登録済み値を維持して使う。取得失敗や空の取得で消さない。
- 主リンクがない既存作品の移行先は未決。値を失わず保持する必要がある。
- 作品側の既存値を「出所未確認」として全件保持する前回の開発側案より、今回の主リンクへの移行指定を優先する。

### 言語

- 各ソースリンクに複数言語を付与できる構造・入力UIにする。
- 取得元から複数言語が得られる場合はすべて保持し、先頭の一つだけへ切り詰めない。
- ユーザーが現行の複数言語取り込み漏れを報告。取り込み元・共通変換・保存・編集・検索の各経路で確認が必要であり、原因コードを特定済みとはしない。
- 過去に保存されなかった言語を既存DBの一値から復元できるとはしない。再取得は別途必要になる可能性がある。
- 既存の作品側言語を各リンクへどう移行するか、複数言語検索の完全一致／包含等の細部は未決。ページ数への主リンク移行指定を言語にも自動適用したことにはしない。

### リンクの役割

- 現時点では本編／サンプル／その他・未確認の3つを基本とするユーザー指定。
- 収録関係は下記のエントリ接続と名前・URLによる参照で扱い、リンク役割に収録先を混在させない。
- フルカラー版等の別版はURLのラベルとして管理する（2026-10-23承認）。刊行区分が同人／商業で異なる場合を原則別作品とする既存合意は変更しない。

### 日付の入力体験

- 普段は日付入力欄を一つにし、「日付を追加」操作で日付とその意味を複数登録できるUIを希望。
- 発売日・公開日等を別の意味として保持する方向で、最初から多数の空欄を並べない。
- 最初の欄の既定の意味、選べる日付種別、任意ラベル、同種の複数日付、代表値の算出の細部は未決。
- 代表日付は優先度最上位の有効ソース群から最古を採用する既存合意を維持。種別を追加することで、発売日とサンプル公開日を無差別に混ぜない規則の詳細化が必要。

### 手動編集・再取得

- 手動編集可能、空欄は取得情報で補完、異なる既存値は比較して採用を選ぶ。
- 空の結果・失敗で既存値を消さない。
- 主リンクの変更でリンク固有情報を移動・消去しない。
- 複数言語の既存値と取得値のマージ／置換／維持の具体UIは詳細化する。

## 2026-10-23に承認された事項

### 収録関係は作品への接続と未登録参照を併用する

収録関係の本体は「単話エントリ→収録先エントリ」とする。特定の販売サイトURLだけへ依存させない。一つの収録先エントリが複数の販売先を持てる。

収録先を個人DBに登録していない場合は、詳細情報の同じ収録先欄に名前と任意URLを保存できるようにする。この未登録参照は本棚に表示する通常エントリの自動作成とは分ける。後で対象エントリを登録したら、利用者が明示的に接続できる。エントリへの接続と収録先URLは排他的な選択にせず、両方を同時に保持できる（ユーザー明示）。

これなら雑誌まで本棚に追加する負担を避けつつ、収録先を後からサイト横断で整理できる。収録先URLを本編ソースとして数えず、単話のページ数や言語を雑誌全体の情報で上書きしない。逆向き関係の表示・多重所属・循環防止等は実装仕様で詰める。

### 別版はリンク役割と独立させる

本編／サンプルという役割とは別に、URLのラベルで任意の版名（例：フルカラー版）を記録する。本編とサンプルの両方に同じ版が存在し得るため、単一選択の役割へ混在させない。独立した版エントリや複雑な版管理機能を必須にするものではない。既存のサイト名ラベルとの表示上の両立や保存方法は詳細設計で決める。

個人側はまとめ方を自由にし、リンクの版ラベルだけで共用作品を自動統合しない。共用の別版関係の厳密な規則まで今回決めるものではない。

### CG枚数は今回追加しない

ユーザーは、CG集に用途が限られ、自動取得が困難であることから専用欄はなくてよいと判断。今回の個人DB改修ではCG枚数の専用入力欄・基本枚数／差分込み枚数・自由文からの推定取得を追加しない。これはページ数の保存・リンクへの移行を取りやめる意味ではない。将来の拡張可能性は残すが実装予定とはしない。

## 開発側提案：未承認

### 日付種別

日付の意味はまず発売／公開／その他を候補とし、その他に任意ラベルを付けられる案。最初の種別はインポーターが根拠をもって判別できる場合だけ設定し、手動時に選択可能にする。年月日以外の精度・予定日の扱いも残す。
