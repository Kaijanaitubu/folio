# F-020：Pawchive投稿メタデータインポーター

現在の状態：2026-10-15に[投稿Favorites出力・元投稿リンク候補](PAWCHIVE-FAVORITES-ORIGINALS-SPEC.md)を追加。以下は初期投稿インポーターの範囲。

実装日：2026-10-14。ユーザーの今回の承認範囲は投稿メタデータの取り込み。元投稿リンクの探索・保存と、PawchiveのFavorites取得は保留。[先行調査](PAWCHIVE-RESEARCH.md)と区別する。

## 対応範囲

- `https://pawchive.pw/fanbox/user/{作者ID}/post/{投稿ID}` とPatreonの同形式。
- `/{service}/post/{投稿ID}` の短いURLは、同じサービス・投稿IDの作者ID入りURLへのHTTPSリダイレクトだけを解決する。解決できない場合は通常URLの入力を案内する。
- HTTP／HTTPS、www、末尾スラッシュ、クエリ・フラグメントの違いは同じ投稿として比較。取得は固定のHTTPSホストへ行う。比較キーはサービス＋投稿IDを使い、FANBOXとPatreonの同じ数値IDは区別する。
- 作者ページ、検索一覧、Favorites、Discord等の別サービスは未対応。
- 個別インポート、編集画面での再インポート、共有、ブックマークレット、ブックマークHTMLに対応。初期版はPawchiveへのログインやキー入力不要。

## 取得内容

公開API `https://pawchive.pw/api/v1/{service}/user/{作者ID}/post/{投稿ID}` と作者の `/profile` を利用する。投稿ID・作者ID・サービスが要求と一致することを検査する。

| 項目 | 仕様 |
|---|---|
| タイトル | 投稿のtitleを使用。本文・作者名をタイトルへ追加しない |
| 作者 | 対応するprofileのname。取得失敗・作者不一致なら空欄＋警告 |
| 表紙 | fileを優先し、なければattachmentsから最初の対応画像を選ぶ。JPEG／PNG／WebPのハッシュ付き画像パスのみ |
| タグ | 投稿のtagsのみ。配列・JSON配列文字列・引用符やエスケープを含む配列形式文字列に対応。null／空配列はタグなし。読めない形式は警告し、他のメタデータを保持 |
| タグ属性 | 未指定で取得し、個別取込の既定設定またはブックマーク取込設定で既存属性頻度の方式を適用。名前・別名の競合は既存の確認処理を使用 |
| ソース | 入力したPawchive投稿URL、ラベルPawchive。元FANBOX／Patreonリンクは追加しない |
| その他 | カテゴリ・言語・ページ数・サークル・シリーズ・キャラクターは推測しない |

画像なしでも登録できる。ZIP・PDF・動画の中身を取得して表紙を作らない。作者アイコンを表紙として使わない。投稿本文・添付ファイル群・公開日時・課金情報はDBへ取り込まない。

## 表紙中継

DBには画像URLのみ保存する。許可する取得元は `file.pawchive.pw/data/{hash path}` と `img.pawchive.pw/thumbnail/data/{hash path}`。原画像がサイズ上限・応答エラー等で取得できない場合、同じハッシュのサムネイルを一度試す。

画像の拡張子・宣言MIMEと実体が一致しない場合があるため、JPEG／PNG／WebPのバイト署名で中継MIMEを決める。HTML等の応答は中継しない。既存の32MB／5分のRAMキャッシュ・同時取得制限を共有し、画像はストレージ・DB・バックアップへ保存しない。

取得URLのホストとパスを制限し、公開IPだけを許可して接続先を固定する。20秒のリクエスト期限、JSON最大4MB、画像最大2MB。任意のリダイレクト先へ接続せず、アカウントCookieを使わない。メタデータ取得は約1秒間隔に抑え、ブックマークジョブの停止・再開に対応する。

## 既存機能との接続

登録済みURLを共有／ブックマークレットから開く場合は、取得せず既存作品を開く。ブックマークの同一URLはスキップする。明示的な再インポートでは既存の単一項目の上書き確認・複数項目の上書き／マージ／維持を使用し、一致するデータは変更しない。

タイトルによる同一作品候補と副リンク追加の確認は既存処理を使い、自動で統合しない。ここで追加する副リンクはPawchiveリンクであり、元投稿を探索する機能とは別。

移行12では、手動登録済みPawchive投稿リンクの比較キーとURL予約を再構築する。URLの表示文字列・作品内容・作品IDは変更せず、以前からある同じ投稿の複数作品も勝手に統合しない。

## 次の段階

Favoritesは認証済み応答・件数・ページ送り・接続方法を確認してから実装する。元投稿URLはAPI応答に直接含まれるとは確認できておらず、取得値からの組み立て・候補探索・確認方法を別途相談する。
