# F-036：共有URLのリンクカード

2026-10-16。ユーザーが掲載情報と画像方針を確認し、実装を承認。[ロードマップ](ROADMAP.md)・[共有仕様](SHARING-SPEC.md)。

## 確定した表示内容

| 項目 | 内容 |
| --- | --- |
| タイトル | 共有時点の作品名 |
| 説明 | 共有時点の作者名・サークル名だけ。未設定項目は省く。両方未設定なら空欄 |
| 画像 | 黒とオレンジのFolio共通ロゴ画像。1200×630 PNG |
| サイト名 | Folio |
| クリック先 | Folioの共有ページ |

当初の表紙・カテゴリ・ページ数を含む案は採用しない。ユーザーは作品内容が分かることを許容するが、リンクを貼っただけでヌード画像が表示される事故を避けたいと指定した。そのため、ぼかした表紙も使用せず、作品に依存しない共通画像に固定する。画像内に作品名等も埋め込まない。

タグ・レビュー・評価・マーク・登録者情報・カテゴリ・ページ数・ソースURL一覧はカード用メタデータへ含めない。個人記録を共有ページ上で公開していても同様。共有ページ本文の表紙・フルレビュー・その他の公開情報や、表紙から主リンクへ移動する動作は維持する。

## 配信と設定

`share_server.py` が最初のHTML応答のheadにOpen GraphとTwitter Cardのメタタグを生成する。JavaScriptや認証を必要としない。名前とタイトルはHTML属性としてエスケープする。英語／日本語の説明ラベルは共有時点のUI言語を使う。

共通画像は `/s/{token}/card.png` で配信する。共有が有効な場合だけGET／HEADに応答し、解除済み・不明トークンは404。外部表紙の取得・中継は行わず、同梱した `static/share-card.png` のみを返す。公開サーバーから `/static/` 全体を公開する変更は行わない。HTML・共通画像ともno-storeと既存の検索掲載抑止を維持する。

絶対URLは公開・私有の両systemdサービスが読む `/etc/folio/sharing.env` の `FOLIO_SHARE_BASE` から作る。リクエストのHostやForwardedヘッダーは使用しない。未設定・不正なURL設定では画像URLとog:urlを省略するため、導入時は両サービスの環境設定を確認する。ドメイン変更時には両方を再起動する。作品情報は共有スナップショットだけを参照し、作品の現在値を後から補完しない。

## 確認方法と制限

対応チャットへ共有URLを貼り付ける。新規発行したURLなら過去のカードキャッシュと区別しやすい。既存の有効な共有URLにも次回取得時からメタタグが付く。既存スナップショットの再作成やDB移行は不要。

カードのレイアウト・省略・実際の表示有無は貼り付け先に依存する。Folioは共通画像のみをカード画像として指定するが、OGPを無視して本文の画像を独自抽出するサービスの挙動までは制御できない。共有解除後は新規のHTML・画像取得を404にするが、外部サービスが保存済みのカードや画像の即時削除は保証しない。主要チャットでの最終的な見え方は利用時の確認が必要で、HTTP検証を実チャットでの確認成功とは扱わない。

## 検証

`media-library/` から `python -m unittest test_sharing -v` を実行。スナップショット固定・作者／サークルのみの説明・属性エスケープ・日英ラベル・未設定・表紙を取得しないPNG配信・GET／HEAD・共有解除・不正ルート・Host非依存・既存共有処理を確認する。実行結果とデプロイ結果は [VERIFICATION.md](VERIFICATION.md) に記録する。
