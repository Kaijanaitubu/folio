# F-027：汎用タイトル・表紙インポーター

2026-10-16。ユーザーは多少の取得漏れを許容し、ブックマークレットのDOM利用とURLだけの取得を併用する実装を承認した。[調査結果](URL-IMPORT-INVESTIGATION.md)と[DOM調査](BROWSER-CAPTURE-IMPORT-INVESTIGATION.md)に基づく。

## 対象と登録導線

- 既存の専用インポーターを優先する。未対応のHTTP／HTTPSページでは汎用処理でタイトルと表紙URLを取得する。作者・タグ・カテゴリ等は汎用処理では推測しない。
- 「Imports → From a link」、編集画面のImport metadata、ブックマークレット、通常共有で利用する。登録済みURLは従来どおり既存詳細を開き、自動で再インポート・上書きしない。対応済みソースの同一作品・別ページ警告も維持する。
- 新規取得結果は未保存の編集画面へ入れる。保存はユーザーが行う。既存作品への再インポートでは、既存の上書き確認と同じ値なら変更しない処理を通す。
- ブックマークHTMLの大量取り込みは、従来の専用対応サイトの選別を維持する。ブラウザーの無関係なブックマークをすべて自動取り込みする変更は行わない。

## ブックマークレット

設定画面で生成するコードを更新した。旧コードもURLだけの入口として利用できるが、DOM取得には保存済みブックマークレットのコードの入れ替えが必要。

開いているページから、URL、タイトル候補、画像候補を取得する。OG/Twitter情報、h1、document.title、表示済みimgを利用し、最大250画像要素から候補12件を選ぶ。DOM画像は表示80×80以上・実寸150×150以上を対象とする。ロゴ等を可能な範囲で除外する。Xの投稿では本文を仮タイトルにし、識別できる場合は対象articleに画像範囲を絞る。OG説明も補完に使う。スレッドの結合は行わない。

Folioへ渡す情報は `version:1 / url / title / images`。タイトル上限500文字、各URL4096文字。候補を削ってエンコード後のcaptureを約20,000文字以内に収める。データはURLフラグメント内に置き、受け取り後すぐURLから除去する。外部ページのCookie、入力欄、HTML全体、FolioのAPIトークンを渡さない。受信側もバージョン・対象URLの一致・型・件数・URL形式を検証する。

DOM候補は取得元ページを実行できた場合の補助情報。CSPやブラウザー側の制限でブックマークレット自体が動かない場合は、通常共有またはURL貼り付けを利用する。Android Chrome／Braveでの実機操作の成否は、本人の利用確認が必要。

## URLのみの取得と併用

未対応サイトでDOMのタイトルと画像が揃っていれば、追加のHTML取得は省く。不足があるときはサーバーから公開HTMLを取得して補完し、DOM側のタイトル・表紙候補を優先する。専用インポーターでは取得結果を優先し、DOM情報は欠落の補完と追加の画像候補に使う。専用処理のエラーを黙って別の結果へ置き換えない。

2026-10-16 F-034修正：専用インポーターが作品名を取得できた場合、ブラウザーの見出しは別タイトルとして追加しない。Hitomiの共通見出しRead Online等が同一作品判定を誤らせたため。タイトル照合は現在の作品タイトル同士だけとし、取得元の別タイトルは編集候補に限定する。[原因・現行仕様](ISSUE-WORK-MATCH-FALSE-POSITIVES.md)。

URL取得は公開HTMLのJSON-LD（Book／Product等）、OG/Twitter、h1/title、imgのsrc・data-src・data-originalを読む。作品名に対応する構造化データの商品画像を優先し、とらのあなの共通OG画像を誤って最優先にしない。Xはプロフィール名を表すog:titleより投稿本文のOG説明を仮タイトルに使う。作者等のメタデータを汎用のJSON-LDから自動登録しない。

通常のOS共有で受け取れるタイトルも補助として利用する。共有先から元ページDOMを読むことはできない。URLしか受信できなかった場合はURLのみの取得となる。

HTTP403、タイムアウト、年齢確認、メタ情報不足などでは、取得できた情報と警告を返して手動編集を続けられるようにする。年齢確認ページやブロック画面の見出しを作品名として採用しない。ただし、あらゆるサイトのエラーページを完全に識別する保証はない。ログイン・CAPTCHA・有料本文の突破は行わない。

## 表紙候補

取得時の画像候補は編集画面の表紙プレビューの下に「Image 1／画像1」等のボタンで表示する。選ぶと表紙URLを上書きし、プレビューを更新する。作品への保存は通常のSave時。候補自体は編集中だけ保持し、DBに新しい候補テーブルや画像データを保存しない。画像URLからの再インポートで候補を取り直せる。

任意の画像URLが表示できる保証はない。外部ページの画像候補には広告や別作品が混ざる場合がある。Getchuの商品表紙だけは、今回確認した固定ホスト・ID対応パスに限定し、正しいRefererを付けた既存RAMキャッシュ経由の表示を追加した。画像自体の永続保存はしない。

**公開共有スナップショットの画像中継は、引き続き固定の対応ソースに限定する。** 未知の画像ホストまで自動で中継・公開する変更は含めない。そのため、個人画面で表示できても共有ページでは表紙が表示できない場合がある。汎用取り込みの完了と、各サイトの共有画像対応・専用メタデータインポーターの完成は区別する。

## 取得制限

- HTTP／HTTPS・80／443のみ。認証情報付きURL、非公開IP、localhost等を拒否する。全DNS応答を検査し、実際のソケットを検査済みIPへ固定する。各転送先でも再検証し、HTTPSからHTTPへの転送を拒否する。
- TLS証明書検証を維持。HTML4MiB、Getchu画像2MiB、gzip展開後にも同じ上限。通常取得は20秒の全体期限、最大9リクエストで転送に従う。匿名Cookieは一回の取得中のメモリだけに保持する。
- 取得の同時実行は3、DNSスレッドは最大4。DNS待ちも期限内に制限し、利用中なら後で再試行できる警告を返す。
- URLの任意クエリや途中ページのフラグメントを一律削除しない。元URLをソースリンクとして保持し、既存の正規化重複判定を通す。
- 任意URLを受ける画像プロキシは追加しない。既存のトークン／Origin確認を通すprivate APIであり、公開共有サーバーへ汎用HTML取得APIは追加しない。

実装：`generic_importer.py`、`importer.py`、`server.py`、`cover_sources.py`、`static/source-link.js`、`static/app.js`ほか。DB移行・既存作品の一括変更なし。
