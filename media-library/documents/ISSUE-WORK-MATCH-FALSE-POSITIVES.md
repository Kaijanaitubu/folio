# 同一作品候補の誤検出調査

記録日：2026-10-16  
管理ID：F-034  
状態：修正・VPS反映済み（2026-10-16）  
関連：[ロードマップ](ROADMAP.md)

## 報告内容

同一作品判定が過剰に候補を出しているように見え、内容が全然関係ない作品まで同一作品として提案される。まず現在の照合機構を調べ、どの条件で候補になるか確認する。

## 予備所見

コードの予備確認で、表示タイトルと保存済みソースタイトルの正規化後完全一致に基づく同名警告、異なるソース間の副リンク統合候補が確認された。正規化では、先頭の角括弧部分をクレジットとして除く場合がある。交差ソース候補は、既知の作者が双方にいて一致しない場合に除外される一方、作者情報が不足している場合はタイトル一致のみで残る可能性がある。画面では同名警告と統合候補が同じ候補選択へまとめられている箇所もある。

この予備所見だけでは、誤候補がどの経路で出たのか、実際の原因が何かは特定できていない。各経路を再現例と照合する。

## 再現と原因

ユーザーは手動統合ボタンを押さず、ブックマークレットの通常インポートで無関係な直近の登録作品が並ぶと報告。提供例はHitomiの画像セット4258318（「七羽さち / 7saki」）。修正前の実HTTPS APIで、URLだけの取得は同名警告・交差ソース候補とも0件だった。一方、同じURLへブラウザーの見出し`Read Online`を添えると、正しい作品名の横にその見出しが`source_titles`へ追加され、無関係な3作品が同名警告、うち1作品が交差ソース候補として返った。

F-027のブラウザー補完が専用インポーターの取得済みタイトルにもブラウザー見出しを別タイトルとして追加していた。保存側でもそれを`work_titles`へ記録し、照合側は履歴・ソース別の別タイトルも同一判定に使っていた。DBの読み取り調査で、異なる3作品に`Read Online`が保存されていることを確認した。実行中の自動統合ジョブは0件だった。既存の統合すべてが正しかった／誤っていたという判定は、この調査だけからは行わない。

別件として、保存済み作品の手動統合画面が無条件に最近40件を渡し、検索欄を空にしたときも全件検索していた。これは通常インポートの再現原因とは別だが、同じ確認画面を使うため混同しやすい問題だった。

## 確定する照合仕様（ユーザー指定）

- タイトルの照合は、登録済み作品の**現在の`works.title`**と、今回登録する**`data.title`**だけで行う。`source_titles`・`work_titles`の履歴・ブックマーク名・nhentaiの別言語／prettyタイトルは照合しない。
- ブックマーク名は、取込時の「ブックマーク名優先」設定で今回の実タイトルに採用された場合のみ、そのタイトルとして比較対象になる。既存のタイトル編集・入力候補・履歴の保存は維持する。
- NFKC・大小文字・空白の正規化と、既存の先頭クレジット角括弧除去は継続する。話・巻・言語・版の保護、別ページリンクの警告、完全一致URLの登録済み判定は変えない。曖昧な類似検索は導入しない。
- `Read Online`などの読み込み・閲覧画面の共通見出しは、タイトル一致の根拠にしない。専用インポーターでタイトルを取得できた場合、ブラウザーのタイトルを取得済みの別タイトルへ追加しない。画像候補の補完と、汎用インポーターのDOM＋URL補完は維持する。
- 元投稿URLの一致は従来のリンク照合として別途提示する。タイトル一致の証拠として偽装しない。保存済みURLの作品詳細への遷移も維持する。

## 確認・自動適用

- 手動の統合ボタンは「統合先を検索」に分ける。最初は一覧を出さず、空欄・空白だけでは検索リクエストを送らない。手動検索結果は同一判定の結果ではないと表示する。自動候補と手動検索結果を区別し、どの作品も初期選択しない。
- バッチの「すべてに適用」／`attach_unique`は、候補が1件で、現在のタイトル・作者が一致し、言語・ページ数に矛盾がなく、途中ページのリンクでない場合だけ自動副リンク追加する。弱い一致や複数候補は確認待ちに残す。明示的に選んだ1件への手動統合は引き続き可能。
- 候補の減少に合わせて、言語違いの別タイトルしか合わない作品や、変更前のタイトルしか合わない作品は自動提案されなくなる。必要なら手動で統合先を探す。
- 過去のタイトル候補・作品・リンクの削除や修復のための自動統合は行わない。DBのスキーマ移行も不要。現在のタイトルを正規化するSQLite関数は接続時に登録するだけで、保存済みDBの構造は変更しない。

## 回帰検証

- 専用処理のタイトルと画像候補を維持し、`Read Online`を別タイトルへ追加しない。
- 汚染した別タイトルを持つ無関係な3作品があっても、通常インポートで同名・交差ソース候補を返さない。プレビューだけでは作品を保存しない。
- 旧タイトル・元タイトル・ブックマーク名・取り込む側の別タイトルを照合せず、現在のタイトル同士なら候補を返す。編集候補データは削除しない。
- 作者不明、ページ数・言語の矛盾、途中ページを含む弱い候補を、自動適用せず確認待ちにする。選択済み1件だけを手動反映し、残りの弱い候補を巻き込まない。
- 手動統合、空検索、検索のクリア、入力の引用符、候補の明示選択、英語・日本語の表示を検証する。

## 反映後の確認

VPSの実HTTPSで提供例4258318を再取得。URLのみ、`Read Online`を添えたブックマークレット相当の入力のどちらも、正しいタイトル「七羽さち / 7saki」を返し、同名警告・交差ソース候補とも0件になった。直前のDB退避と配備前後の全テーブルハッシュ一致、SQLite整合性ok・外部キー違反0件を確認した。保存済み作品や過去のタイトル情報は変更していない。Folioの画面を再読み込みすると新しいフロントエンドを利用できる。既存のブックマークレットの入れ替えは不要。

## 2026-10-17：波線表記による候補漏れの修正

DLsite作品c8e3c2eb024b48f3a36dc62dfef5475cとHitomi作品f4e299cf57f54b16887cce8fcae8f2a6の現在タイトルを読み取り調査。全角チルダ「～」U+FF5EはNFKCでASCII「~」になる一方、波ダッシュ「〜」U+301Cは残り、照合キーの2か所が異なっていた。作者は共通。ユーザーが波線の同一扱いを承認。

タイトル専用のtitle_keyで、既存NFKC処理に加えてU+301CをASCIIチルダに正規化する。これにより「～」「〜」「~」を同一扱いにする。作品の表示タイトル・保存値、タグ／作者の正規化は変更しない。巻数・話数・ハイフン・波線の有無を無視する変更は行わない。現在タイトル限定、作者の競合、別サイト候補、弱い証拠で自動統合しない条件も維持する。

既存タイトルは検索時にwork_title_key関数で評価するため、DBの書き換えや履歴タイトルの再登録は不要。新しい照合キーが候補警告と副リンク統合提案の両方に適用される。今回の既存2作品を自動統合する変更ではない。

## 同一作品候補の緩和案（未承認・未実装）

ユーザーはF-038を先に実施し、緩和案は改めて説明するよう指定。現在の波線正規化以外の判定は変更しない。検討案は「正規化タイトル一致、または作者一致＋空白・区切り記号差なら同一作品候補」「作者一致＋十分なタイトル類似なら似ている作品」の二段階。巻数・話数・前後編等の明確な相違は除外し、短すぎるタイトルやシリーズ名だけの一致は候補にしない。曖昧な候補は理由付き上位数件に限定し、自動統合・一括すべて適用の根拠にしない。閾値・区切り記号の範囲・実データでの候補数を確認してから実装判断する。
