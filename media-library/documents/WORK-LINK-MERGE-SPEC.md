# 作品詳細からのリンク統合

2026-10-15 実装。新規・既存作品の編集画面で「Import metadata」の隣に既存の副リンク追加ボタンを表示する。詳細画面に追加した統合ボタンは利用者の要望により削除した。既存作品は保存済みの全リンクを統合する。未保存の編集がある場合は先に保存するよう案内し、変更を勝手に保存・破棄しない。既存の候補選択画面を使用し、タイトルの検索に対応する。候補にはタイトル・作者・主リンクを表示し、自分自身とゴミ箱の作品は除外する。

統合前に元・先のタイトル、追加リンク件数、リンクのみを移すことと元作品のゴミ箱移動を確認する。キャンセルでは変更しない。確認後に作品が変わった場合は中止し再確認する。

元の全ソースリンクを先へ副リンクとして追加する。先に同じ正規化URLがあれば追加しない。先の主リンク、タイトル、作者・タグ等、評価、レビュー、マーク、画像を維持する。リンクのない統合先にも副リンクとして追加できる。第三の作品に同じURLがある場合は競合として中止する。対応インポーターの有無を問わず、任意の保存済みソースリンクを対象にする。ネットワークで作品メタデータを再取得しない。

追加と元のゴミ箱移動は一つのトランザクションで行う。元のリンクと各項目はゴミ箱に保持する。既存の30日保持期間が適用される。操作履歴には先へのリンク追加を編集として記録し、取り消しでリンク追加を戻せる。元作品の復元は別途ゴミ箱から行う。統合後に先のリンクが変更されていれば既存の履歴競合ルールに従う。

検証：HTTPテストでリンクのみの反映、主リンク維持、元の情報保全、履歴取り消しと復元、リンクなしの先、同一作品・不存在・ゴミ箱・別ユーザーの拒否、確認後の変更と未確認実行の拒否を確認。既存のインポート画面回帰テストも通過。

既存作品の候補では自分自身を除外し、「別作品として新規登録」の選択肢を表示しない。新規作品の従来の副リンク追加は維持する。


## 2026-10-15 統合後のゴミ箱リンクが再取込を妨げる問題

原因：リンクの統合は統合先へ副リンクを追加し、統合元を元のリンク付きでゴミ箱へ移す。復元・取り消しのために必要な保持だが、`exact_sources` が登録中・ゴミ箱を区別せず検索していた。明示した再インポートで統合先IDを除外しても、ゴミ箱の統合元が残り「登録済みURL」と判定されていた。

修正：正規化URLに一致する登録中作品が一つでもある場合は、それらを優先して返す。その後に呼び出し元の除外IDを適用する。登録中の統合先だけが一致する場合、その作品からの再インポートは競合なしとなる。別の登録中作品も一致する場合は引き続き競合する。登録中作品が一つもなければ、従来通りゴミ箱の一致を返して確認を要求する。

この共通ルールを個別取込・ブックマークレット／共有の登録済み判定・バッチの重複確認・元投稿リンク候補へ適用する。作品やリンクの削除、ゴミ箱の自動消去、重複作品の自動統合は行わない。既に統合した作品にもデータ移行なしで適用される。統合のリンク履歴取り消しとゴミ箱の復元は維持し、復元により本当に複数の登録中作品が生じれば通常の競合として扱う。

HTTP回帰テストで、統合→再取込、登録済みリンクの詳細への遷移、連続統合、復元後の実競合、統合先がURLを外した後のゴミ箱確認を検証する。
