# 購入一覧インポートの現状と保留理由

2026-10-15更新：FANZA同人を再開。本人のログイン済み購入一覧をコミックで絞り込み、画面合計28作品と全28商品リンクの一致を実確認した。既存取り込み向けHTMLを作成し、全件が対応URLであることを確認。Folio Importsに再利用可能な出力ブックマークレットを実装。認証済みAPIへの接続ではなく、表示中の購入一覧を読み取る方式。以下は2026-10-14の保留記録で、DLsiteとDMMブックスの未確認事項は引き続き保留。


記録日：2026-10-14。DLsite／FANZAの購入一覧をFolioへ取り込む相談の途中経過。実装済み商品ページインポーターと、未完成の購入一覧取得機能を区別する。

## 現在できること

- 通常のDLsite／FANZA／DMMブックス商品URLから、既存の商品インポーターで作品メタデータを取得できる。DLsite Playは個別作品IDから通常の商品ページを取得する。PlayシリーズURLは未対応。
- DLsiteについて、第三者ライブラリの取得手順を参考にした、通信処理を外部から渡す試作とオフライン変換処理を作成済み。合成データで検証した。詳細は [試作資料](DLSITE-PURCHASES-PROTOTYPE.md)。
- 試作形式の取得済みJSONを対象選別・件数照合し、既存のブックマーク取込向けHTMLへ変換できる。このJSONはDLsite公式のエクスポート形式ではない。

## まだできないこと／確認していないこと

- 現在の実アカウントへの認証、購入一覧APIからの実データ取得、全件性、認証期限、販売終了作品の網羅性は未確認。
- Folioには購入一覧の実接続、ログインUI、ワンクリック取得、購入状態の自動反映を追加していない。
- 第三者アプリ向けの公式購入履歴API・APIキー・一覧エクスポート・連携許可は、今回の調査では確認できなかった。存在しないとは断定しない。

## 紹介した「API」の意味

[dlsite-async のPlay実装](https://github.com/bhrevol/dlsite-async/blob/main/src/dlsite_async/play/api.py)は、DLsite Play内部の購入件数・作品ID・作品情報の経路を利用する第三者クライアントの実装例。公式に公開・保証された外部連携APIとして確認したものではない。実装例の存在だけでは、現在のサービスとこのアカウントで利用できる証明にならない。

ライブラリのインストール・実アカウントを使った実行はしていない。Folio側に作った試作は、取得後の変換と、認証・実通信を含まない取得手順の中核まで。

## 作業が止まった理由

DLsite Playと購入履歴の確認時に、ChatGPT／Codexのブラウザ操作ツールが「site-safety policy」で操作を拒否した。DLsiteサーバーからのAPIエラーや、DLsiteの利用規約による拒否を確認したものではない。詳しい判定理由は提示されず、ユーザー承認やAuto-reviewは実行されなかった。

この拒否には同じ取得を別ブラウザ・Cookieの取り出し・外部スクリプト等で迂回しない指示が付いていたため、今回の作業では、Folioから実行して同じ購入データを取得する形でも検証を進めていない。これは完成したFolioの一般的な技術能力と別の、このエージェント作業に対する制限。ユーザー自身の通常のサイト操作を禁止するものではない。

会話では「ユーザーが検証すれば進められる」「ブラウザを使わない方式なら試せる」と受け取れる説明をした後で訂正した。購入一覧取得の成功や実用化は、まだ一度も確認していない。

## FANZA／DMMの確認範囲

ログイン済みFANZA同人の一覧で、購入済み詳細URLのID、漫画・音声の形式表示、スクロールに伴う追加読み込みを確認した。DMMブックスではシリーズ棚から購入済み巻ごとの商品URLへの導線を確認した。いずれも全件取得や内部API認証の検証は未完了。個人の購入情報や認証情報をドキュメント・Gitへ保存していない。

## 再開時の基準

取得経路・許可範囲・認証方法を確認できる資料を用意し、実通信が可能な環境で少量取得、件数照合、全件性を順に検証するまで「購入一覧対応済み」と扱わない。取得済みの認証情報を含まない商品一覧を扱う変換処理は、実接続とは独立して扱える。

当面は購入一覧の接続作業を保留し、F-020 pawchiveインポーターの実現性調査へ移る。
