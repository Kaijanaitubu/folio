# 正式版：共用タグ辞書と概念検索の設計議題

2026-10-18作成、2026-10-24更新。共用辞書の採用方針と末尾の基本構造・運用を合意。詳細な関係検索・ベクトル等の方式は引き続き提案であり、今回の記録は辞書の実作成や実装の開始指示ではない。[会議記録](PUBLIC-EDITION-DISCUSSION.md)。

## ユーザーが示した方針

- 個人DBの通常のタグ付与は共用タグ辞書から選ぶ方式にする。
- 共用辞書に対応しないタグを、作品の公開タグ集計へ加えない。ただし辞書外の利用状況は内部で集計し、共用辞書に採用するか人手で精査する。
- 共用辞書自体も人の手で作ることを許容。一般の作品照合・集約を省力化する方針の中で、タグ概念の編集には人手をかける意思がある。
- 成人向けのニッチな行為・シチュエーション・心身の特徴・ジャンルを細かく正確に検索できることを重視する。
- 近いが異なる概念を区別したうえで、近さ・多次元の関係を検索に使いたい。概念ベクトルは検討候補で、手法やモデルを指定済みではない。

## 開発側提案：共通概念と個人利用の接続

共用概念ID・言語別名称／別名・定義を持ち、個人側には選択した概念への対応を保存する。辞書外の個人タグは保存を許容し、作品公開集計とは別の運営用候補にする。登録時の説明で、共用タグと辞書外タグの扱いを明示する。内部候補の文字列を一般公開しない。候補の利用人数や付与状況は精査に使うが、件数だけで自動採用しない。

同じ概念への複数の表記・男女属性があっても公開基本寄与は同一人・同一作品で1件。属性付き付与の情報自体は失わない。辞書外から共用へ採用された時、既存寄与を再集計する方式は要相談。概念の定義変更・統合／分割で既存タグを無断で別の意味に置換しない移行・履歴も必要。

## 開発側提案：明示的な概念関係を検索の基礎にする

- 同義・表記差：同じ概念として言語別名等に対応。単に近い語を同義として統合しない。
- 上位／下位：大きな分類とより細かい分類。必ず一本の木に押し込めず複数の関係を許容する案。
- 関連：意味的に近いが互いに包含しない概念。
- 混同注意：似ているが意図的に区別すべき概念。関係を持つだけで自動的に検索を広げない。

参照：[W3C SKOS Primer](https://www.w3.org/TR/skos-primer/)。多言語名・概念ID・階層／関連関係の整理の参考であり、RDFや特定DBを採用する決定ではない。混同注意や作品内の役割等はFolio向けの追加設計候補で、すべてがSKOS標準そのものとはしない。

男の娘・女装男子・tomboy・ディックガール等は、名称が近い・共起するというだけで同一概念や翻訳同義語としない。意味の境界・言語文化差・作品上の用法を辞書で決め、必要な別概念を保つ。ここで各用語の厳密な定義や上下関係は断定しない。

## ベクトルの役割（提案）

説明文等から得る埋め込みは、似た概念の候補や自然文検索の入口に使う候補。ベクトルの近さは同義・包含・作品内の存在・支持率を保証しない。厳密な条件検索や除外検索の判定を近似検索だけへ置き換えない。自動の辞書統合・男女属性の推定に直結させない。

検索は、同義表記だけをまとめる厳密検索、下位概念を含む検索、関連概念の提案を区別する案。近いタグを黙って追加しない。希望する概念と近接するが不要な概念を除外できることを優先する。モデル・費用・精度・評価データは別途検証する。

## 別に検討が必要な精密検索

作品単位にタグがあるだけでは、同じ登場人物に二つの特徴があるか、別々の人物に分かれているか、誰が誰に行うかは判別できない。ニッチな条件検索でどこまで区別したいか、人物・役割・場面単位の付与を導入するかは別の設計議題。既存の男性／女性／属性なしではその関係を保証できず、概念ベクトルだけでも解決しない。現時点で複雑な場面注釈を実装必須と決めない。

## 次に決めること

1. 辞書外タグの作成・候補提出・私的管理マークの画面上の区別。
2. 初期辞書の候補源は2026-10-24に下記4サイトへ決定。実際の収集方法・人手編集の担当と採用ルールを詰める。
3. 定義・別名・関係・統合／分割の編集権限と履歴。
4. 通常検索の展開範囲、除外の意味、信頼度・男女属性との組合せ。
5. 人物・役割・場面の精度をどこまで扱うか。
6. ベクトルを導入する前に、代表的な「探したい／混ざってほしくない」検索例で評価基準を作る。

## 2026-10-18：検討範囲の補足

ユーザーはタグ概念の設計を独立した会議で再検討する方針。初期は作品単位の付与・性別属性・タグごとの適用定義と投票で整理する方向で、人物・場面ごとの詳細注釈は必須にしない。関係やベクトルの導入範囲は集合知の入力負荷と釣り合うかも含め未決。タグ別に行為者／対象者のどちらへ属性を適用するかを定義できるが、取得元の属性とFolio定義の対応確認は必要で、名目上の互換性だけで全件の意味が一致するとみなさない。

## 2026-10-24：辞典の基本構造・運用を了承

ユーザーは次の基本案を概ね了承し、初期構築時の既存タグ対応付けについて下記の訂正を指定した。

- タグは固定概念ID、言語別名称、同義の別名、短い定義、属性の適用説明、関連概念、状態・変更履歴を持つ。
- 男性／女性／属性なしは共通概念とは内部で分ける。似ているだけの語を同義として統合せず、別概念と関係を保持できる。
- 名称・定義・翻訳・関係が全て揃わないと登録できない仕組みにはしない。日英の片方だけでも登録可能とする。
- 個人DBの表示名・別名編集は、共用辞典の名称や定義の変更と分離する。
- 一般利用者は辞典外タグを個人保存し、追加・訂正を提案できる。運営が採用・保留・却下等を判断する基本方式とする。
- 誤字・訳語の修正と、概念の意味変更を分ける。意味の大きな変更は新概念・分割等を検討し、過去の付与・投票の意味を黙って変えない。統合・分割の具体的な票・寄与の移し方は未決。
- 作品へのタグ付与の適否投票と、共用辞典の定義への訂正は別系統とする。

### 既存タグとの対応付けについての訂正

共用タグ辞典はまだ存在しないため、初期構築の独立した必須工程として「既存の共用タグへの対応付け」を先に作る必要はないというユーザー意向。ユーザー自身の個人DBと作成中の共用辞典の対応付けは、辞典を制作しながら本人が進める。

今回、既存個人DBへの自動対応付け・一括移行ツールの制作を新たに要求されたものとして扱わない。先の開発側案の「既存タグへの対応付け」を次の必須会議・実装工程として押し戻さない。一方、辞典内の同義語整理や将来の統合・分割の具体規則まで、この発言だけで全て決定したとは扱わない。

現時点では構造と初期整備方針の記録。詳細な語彙採用基準、取得方法、統合・分割時の履歴・寄与、概念関係を検索へどう適用するかは引き続き相談する。
