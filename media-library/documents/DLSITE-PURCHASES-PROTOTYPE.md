# DLsite Play購入一覧取得の試作と現在の接続範囲

2026-10-14。ユーザー依頼「ログイン済み前提で購入一覧APIを使い、実装できるところまで」に対する試作。[調査記録](STORE-PURCHASES-RESEARCH.md)と[既存の商品インポーター](STORES-SPEC.md)を参照。

## 実装した部分

`media-library/dlsite_purchases.py` に、認証済みJSONリクエスト関数を引数として渡す一覧取得の中核を実装。外部の[dlsite-async開発者による実装](https://github.com/bhrevol/dlsite-async/blob/main/src/dlsite_async/play/api.py)で確認した相対経路に沿って、購入件数、購入ID、100件ずつの作品情報取得を順に実行する。画像・作品本文・ダウンロードトークンのAPIは使用しない。

- 件数：GET `/api/v3/content/count?last=0` の `user`。
- 一覧：GET `/api/v3/content/sales?last=0` の各 `workno`。
- 作品：POST `/api/v3/content/works` に100件以下のID配列。返却された `works` を照合。
- キャンセルと取得進捗を受け取れる。認証・HTTPエラーは呼び出し元へ返し、部分一覧を成功扱いしない。未知の商品IDや応答内の重複を拒否する。

この中核はネットワーク接続を持たない。`request(method, relative_path, body)` は呼び出し側で用意する契約であり、今回提供するCLIからも本番Folioからも実APIへ接続できない。実際の認証・通信が完了した実装と混同しない。

取得結果は商品ID・タイトル・作品形式だけの `folio-dlsite-play-purchases-v1` データへ整形する。Cookie・認証トークン・アカウント情報・購入日・注文番号・金額などを引き継がない。既に渡された同形式のファイルはオフラインで検証・変換できる。この形式はFolioの試作契約で、DLsite公式のエクスポート形式ではない。

## 対象の選別と既存Folioへの入口

[作品形式コードの開発者資料](https://github.com/bhrevol/dlsite-async/blob/main/src/dlsite_async/work.py)に基づき、RJ／BJかつ漫画のMNG／SCM／WBT、CG・イラストのICGを対象とする。ゲーム・音声・小説・未対応商品群は対象外レポートに残す。形式・タイトル・作品情報が欠ける場合や未知の形式コードは確認対象。タイトルから形式を推測しない。

件数が一致し、各IDのメタデータが揃い、確認対象がなければ、既存Folioが読めるNetscapeブックマークHTMLへ変換する。リンクはPlayの個別作品URL、ブックマーク名はAPI上の日本語タイトル優先。通常のImports画面でプレビュー・選択・タイトル優先・タグ属性方式を選んで取り込む。

以後の動作は既存のバッチと同じ。商品メタデータは通常のDLsite商品ページから取得する。Play／通常商品リンクが登録済みならスキップし、別サイトの同一作品候補は確認待ちにする。購入済みマークの自動付与や既存評価の変更はしない。

商品ページが販売終了などで取得できない場合は既存ジョブで失敗として表示される。Playメタデータだけで作品を登録するフォールバックは今回未実装。API上のタイトルを優先したい場合はブックマーク名優先を選べるが、商品ページ取得そのものを省略する機能ではない。

## オフラインの動作確認

以下は `media-library/` を作業ディレクトリにして実行する。[例のJSON](examples/dlsite-play-purchases.example.json)は架空の検証データであり、実アカウントの購入情報ではない。例から生成したリンクを個人ライブラリへ登録する用途ではない。

```powershell
python convert_dlsite_purchases.py --input documents/examples/dlsite-play-purchases.example.json --output test-output/dlsite-purchases-example.html --report test-output/dlsite-purchases-example-report.json
```

期待結果は3件中、漫画・CGの2件が候補、音声の1件が対象外。ファイルは12MB以内、一覧は10万ID以内。既存出力ファイルの上書きは拒否する。件数の不一致、取得漏れ、未知の形式などがある場合はHTMLを作らず、任意指定のレポートだけで原因を確認できる。

実データファイルを将来扱う場合、JSON・HTML・レポートはいずれも個人の作品一覧になる。認証情報は含めないが、ソースコードやGitに入れる資料とは分けて保存する。API応答の生データやブラウザ通信ログをそのまま受け付けるCLIではない。

## 未接続部分と検証制限

ブラウザでDLsiteにログインしても、別プロセスのFolioサーバーがその認証を自動で利用できるわけではない。今後の実用化には、本人が管理する認証済み環境から安全にJSONリクエストを行う通信層が必要。この通信層・ログインセッション接続・UIのワンクリック取得・無人同期は今回未実装。

将来の通信層は固定ホスト・固定パス、TLS検証、JSONサイズ上限・タイムアウト、逐次取得間隔、セッション期限切れ・追加認証・429への処理が必要。件数APIと一覧APIの対象範囲が一致するか、販売終了・完全削除・特典などが漏れないかも実アカウントで確認する。未確認の範囲を認証を含めて動作保証しない。

この環境のブラウザ操作ツールはPlay／DLsite購入履歴へのアクセスをサイト安全ポリシーで拒否しているため、今回はその画面へ接続する操作も、別ブラウザ・Cookie抽出・外部実行でその拒否を迂回する操作も行っていない。公開開発者資料と合成API応答だけで試作した。認証情報をチャットへ渡す必要はない。

現在完成しているのは「API取得手順の中核→対象選別→件数照合→既存ブックマーク取込用HTML」の部分。実アカウントから一覧を取り出す入口は未完成であり、Importsに購入一覧の接続ボタンは追加していない。
