# Folio — F-002・F-003・F-013 実装仕様

確定日：2026-10-12。ユーザーが仕様と実装を承認済み。この資料は、v2.0要件仕様書のタイトル一意制約および旧インポート仕様に優先する。

## 1. 作品とリンクの識別（F-002）

- 作品の主キーは既存の内部ID。タイトルの重複を許可する。リンクなしの手動登録も許可する。
- プライマリリンクは変更可能な代表リンク。重複判定は所有者内の全リンクを対象とし、セカンダリも含む。
- 同じ表示ページを指すURLは登録済みとして扱う。新規取込はスキップし、別作品への同じURLの保存は拒否する。現在編集中の作品自身のリンクは除外する。
- URLの違う同名作品は新規作品になる。タイトル・作者・Hitomi作品IDから既存作品へ自動反映しない。
- Hitomiの同一作品IDの別ページは警告し、登録可能。単独取込は確認画面、一括取込はプレビュー・最終結果で提示し、バッチを中断しない。
- ブックマークレット／リンクから開く導線は、登録済みURLなら詳細画面を開き、インポーターを呼ばない。以前から複数登録されている場合は選択画面を表示する。

### URL比較規則

表示用の元URLは保持し、比較用キーだけを正規化する。外部サイトへのリダイレクト取得は行わない。

| 差異 | 比較 |
|---|---|
| 前後の空白、ホスト名の大小文字 | 同じ |
| HTTP／HTTPS、先頭の `www.`、標準ポート80／443 | 同じ |
| 空のパスと `/`、末尾の空クエリ `?`／空フラグメント `#` | 同じ |
| URLの非予約文字のパーセント表記 | 同じ。予約文字のエスケープは維持 |
| 意味のあるクエリ、パスの大小文字、末尾スラッシュ（空パス以外）、任意フラグメント | 区別。クエリの並び替えや追跡パラメータ削除はしない |
| Hitomi readerのページ指定なし／`#1`／`#01` | 第1ページとして同じ |
| Hitomi readerの `#2` と `#3` | 別ページ。作品ID一致の警告のみ |
| Hitomiの作品紹介ページとreaderページ | 別URL。作品ID一致の警告のみ |

非HTTP(S)、資格情報入り、不正ポートは拒否する。Hitomi以外のURLも手動登録では許可するが、自動取込対象は引き続きHitomiのみ。

### 同名作品の警告

個別インポートでは保存前に、同名の既存作品のタイトル、プライマリリンク（なければ未設定）、作者名を示す。続行／キャンセルを選べる。同名を理由に保存を拒否しない。一括取込は登録後のレポートで同じ情報をまとめ、各作品の詳細へ移動できる。取込元の警告と重複URLによるスキップは区別する。

2026-10-16 F-034：同名の照合は登録済み作品の現在のタイトルと、今回登録するタイトルだけを対象にする。過去のタイトル・元サイトの別タイトル・保存されたブックマーク名は照合根拠にしない。ブックマーク名を今回のタイトルとして採用した場合だけ、その現在タイトルとして比較する。入力候補・来歴は維持する。[原因・現行仕様](ISSUE-WORK-MATCH-FALSE-POSITIVES.md)。

## 2. ブックマーク名と来歴（F-003）

- HTMLブックマーク取込画面に、取込全体の「取得タイトル優先／ブックマーク名優先」を置く。初期値は従来互換の取得タイトル優先。ブラウザーに前回の選択を記憶する。
- 優先値が空ならもう一方を採用し、双方が空なら失敗として手動確認を案内する。空欄判定には前後の空白を除く。サイトの日本語タイトルを優先する既存取得処理は維持する。
- メタデータ取得自体が失敗した場合は失敗・再試行扱い。ブックマーク名だけで情報取得に成功したと見なさない。
- 選択方式はジョブへ永続保存し、再起動・再試行でも同じ方式を使う。
- 新しく登録した作品に、元のブックマーク名、元URL、取得タイトル、フォルダー、選択方式、取込時刻を内部来歴として保存する。編集可能なリンクラベルとは独立させ、タイトル変更・再インポート・通常保存で失わない。
- 通常の詳細画面には元の名前を表示しない。編集画面でタイトルにフォーカスすると、保存されたブックマーク名を候補として示す。候補ボタンのタップ／クリック／キーボード操作は、入力済みのタイトル全体を選択した名前で上書きする。追記はせず、保存ボタンまでDBは更新しない。タップ中のフォーカス移動で選択を取りこぼさない。
- 同じURLをスキップした場合は既存作品の名前や来歴も変更しない。ジョブにはスキップ結果を残す。
- 既存の成功済み `job_items` に作品IDと名前が残っていれば来歴へ移す。復元できない情報は推測しない。複数の元の名前は候補として重複を除いて提示する。

## 3. 明示的な再インポート（F-013）

対象は作品の編集画面から利用者が押すインポート。登録済みURLから開く導線やブックマーク取込で既存作品を自動更新しない。

タイトル、表紙URL、カテゴリ、言語、ページ数は従来どおり、既存値と異なる取得値を採用するかチェックボックスで選ぶ。初期値は既存値を維持する。

作者、サークル、タグ、シリーズ、キャラクターは項目ごとに次を選べる。初期値は従来互換のマージ。

| 方式 | 取得値が空でない場合 |
|---|---|
| 上書き | 取得結果の集合に置換。取得結果にない作品への関連付けは外す。メタデータ辞書自体は削除しない |
| マージ | 既存値を残し、新しい取得値だけ追加 |
| そのまま | 既存値を維持 |

既存値と取得値が一致する項目は変更せず、確認画面から省略する。単一値は値の一致、複数値は別名解決後の集合として比較し、並び順や重複要素は無視する。メタデータIDを優先し、ID未確定の値は名称と性別で比較する。タグの性別違いは別の項目とする。一致した既存配列の並び順・表示情報も維持する。全項目が一致する、または選択した反映方法で結果が変わらない場合は「変更する情報はありません」と表示し、編集内容を変更しない。

既存値が空なら非空の取得値で自動補完する。取得値が空なら、方式を問わず既存値を維持する。評価・レビュー・購入済みは対象外。

別名の候補を既存メタデータへ解決してから重複を除く。タグは名称と性別の組み合わせで識別し、異なる性別を統合しない。曖昧な別名は選択を求める。確認画面には既存値と取得値を表示する。キャンセル、取得失敗、確認中の画面遷移では編集中のデータも変更しない。反映しても通常の保存操作までDBは更新しない。

## 4. 保存・API・移行

- スキーマ移行でタイトル一意制約を除き、検索用のタイトルインデックスを維持する。ID、時刻、関連付け、リンク、評価、既存ジョブを保全する。
- リンクに比較用キーを保存し、索引を付ける。所有者とキーを一意にするURL登録台帳を設ける。保存は `BEGIN IMMEDIATE` で照合と書込みを直列化し、同時取込も重複させない。
- 旧版で許容されていたURL重複は削除しない。台帳は代表を一件保持し、照合では既存の全リンクも確認する。既存作品自身に既にあったキーの保持は許可し、新しい衝突を拒否する。旧重複を自動統合しない。
- 既存DBの移行前にSQLiteバックアップを取得する。移行はトランザクションで行い、外部キー・整合性を確認する。失敗時は移行を確定しない。
- `POST /api/source-check`：読取り専用。正規化による完全一致を先に返し、一致しなければHitomi作品IDによる別ページ候補を返す。
- `POST /api/import`：他作品の登録済みURLは取得前に拒否。編集対象IDの自身のURLは再取込可能。取得結果に同名作品候補と曖昧な別名候補を付ける。作品は保存しない。
- `POST /api/bookmarks`：ファイル内の正規化重複、登録済みURL、別ページ候補をプレビューへ返す。
- `POST /api/jobs`：選択したタイトル方式を保存。登録済み／バッチ内重複は `duplicate_url` として記録する。処理直前と保存トランザクション中も再確認する。
- ワーカーは作品・来歴・最終ジョブ結果を同一トランザクションで確定する。同名は `added` の警告、完全URL重複は `duplicate_url`。既存の失敗／再試行／中止履歴は保持する。
- 作品取得APIは編集用の元ブックマーク名候補を返す。通常保存APIから来歴を書き換えることはできない。
- 新しいUIとメッセージは英語・日本語に対応する。

## 5. 完了条件

1. 同名・別URLを個別／バッチで登録でき、作者・代表リンク付き警告を確認できる。
2. HTTP／www／空クエリ等の同値URL、セカンダリURL、同時保存、バッチ内重複を防ぐ。自身の再編集とURLなしの作品を許可する。
3. Hitomiの別ページは警告だけで登録でき、登録済みリンクから開くとインポートが走らない。
4. 両タイトル方式と空欄フォールバックが動き、来歴・候補が保存／再起動後も残る。
5. 上書き・マージ・そのまま、空欄補完、空取得の維持、性別違い、別名解決、キャンセルを検証する。
6. 旧DB移行で作品・メタデータ関連・評価・リンク・ジョブを欠損させない。既存URL重複も保全する。
7. 回帰テスト、英語／日本語UI確認、稼働DBのバックアップと整合性検査を完了し、検証記録とロードマップを更新する。
