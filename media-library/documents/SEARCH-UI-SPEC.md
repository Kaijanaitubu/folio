# F-029・F-028：検索バー配置と入力候補

2026-10-16。ユーザーが実装を承認。個人版の検索文法や検索結果の意味は変更せず、入力と配置を改善する。

## F-029：独立した検索バーと操作ボタン

- 検索フォーム、新規追加、ランダムの各ボタンを分離する。追加・ランダムの位置は検索フォーカスの前後で維持する。複数選択を解除する×ボタンも追加ボタン側に留まる。
- 検索入力へフォーカスすると、検索フォームだけが画面上部へ移動する。スマホ幅700px以下では左右いっぱいに広がり、PCでは内容領域の上部に移動する。フォーカス解除で下部へ戻る。
- 既存の320msの移動アニメーションを検索フォームへ適用し、横位置と幅の変化も補間する。移動中の切り替えは現在の描画位置から始める。prefers-reduced-motionを尊重する。
- スマホでは、検索開始前の画面高さを保持して追加・ランダムを下端に留める。キーボードで表示領域が縮んでも、入力欄の上へボタンを押し上げない。キーボードに覆われた下側のボタンが見えなくなる場合はある。検索以外の入力中は従来どおり下部ドックを隠す。
- 候補リストはフォーカスした検索バーの下へ展開し、表示領域内の高さに制限して内部をスクロールできる。

実装は`static/app.js`と`static/theme.css`。画面幅の切替やvisualViewport更新を監視する。Androidの実機キーボードを自動操作して検証したという意味ではなく、実ブラウザーの390×844／390×480表示で高さ縮小時の位置を確認した。

## F-028：検索候補

新規`search_suggestions.py`が検索文法に沿った候補を生成し、`static/search-suggestions.js`が表示と選択を担当する。

- `:`より前では、検索項目名を入力に応じて提示する。空欄でのフォーカスでも一覧を開く。項目名を選ぶと`category:`などを入力し、続けて値の候補を開く。
- 項目はtitle、review、author、circle／group、tag、female、male、none／neutral、series、character、category、language、pages、source、url、label、mark、mark1〜5、bought、現在存在するratingN。互換表記も候補に含める。存在しない評価軸は候補に出さない。
- カテゴリは現在の5種の英語キー・日本語名を選べる。言語はjapanese／日本語と登録済みの値。作者・サークル・タグ・シリーズ・キャラクターは正規名と別名を照合し、選択時は現在の主名称を入力する。属性で絞るときは、件数上限を掛ける前に属性を絞り込む。
- マークは31組の包含条件・31組の完全一致・none・anyの64候補。個別マークとboughtはyes／no／true／false。マークのラベルは現在のユーザー設定を反映する。
- 評価は各軸の1〜最大値と整数比較、未評価の否定条件。pagesは代表値・比較条件に加えて、入力中の有効な任意整数を候補として確定できる。範囲外の評価値を提案しない。
- ソースのURL・ラベル、タイトルの一致候補も利用する。sourceではドメインとラベルを提示する。可変データは現在の所有者のデータだけを読み、作品に依存する候補からゴミ箱を除く。自由入力値の例は、それが登録済みデータであることを保証しない。
- 検索式全体の末尾ではなく、カーソルがある検索トークンだけを置き換える。空白によるAND、`/`によるOR、先頭の`-`、引用符・エスケープを維持する。空白、スラッシュ、引用符、バックスラッシュ、括弧を含む値は引用符を付ける。ORの直前に余計な空白を足さない。
- 矢印キーで候補を選び、Enterで確定、Escapeで閉じる。候補未選択のEnterは検索実行。日本語変換中は候補選択・検索確定を横取りしない。変換直後の同じEnterによる誤実行も抑制する。
- 150msの待機と応答世代チェックを使い、古い入力への応答や別画面・変換中の応答で候補を上書きしない。タップ時は入力フォーカスを保持する。combobox／listbox／optionと選択状態を付ける。

新クライアントは`GET /api/suggestions?scope=fields|values&field=…&q=…`を使う。scopeを付けない旧クライアントのマーク等の候補契約は維持する。大量データの候補には上限を置く（メタデータ25件、自由入力の候補25件など）。予約語・カテゴリ・マークの固定選択肢は列挙する。

## 確認

- WindowsのPython全291件がOK（環境依存3件スキップ）。Node19本が成功。Linuxの隔離環境でも検索・HTTP関連38件が成功。
- 全検索項目、全カテゴリ表記、マーク64条件と4種の真偽値、評価範囲・未評価を実際の検索コンパイラーで検証。正規名・別名・属性、所有者、ゴミ箱除外も確認。
- カーソル途中、引用符内のスラッシュ・引用符・括弧、OR／NOT、項目→値の連続入力、IMEイベント、古い応答、アニメーションと高さ保持を検証。
- 390px幅の実ブラウザーで、検索フォームは上端0px・幅390pxへ移動し、追加／ランダムはフォーカス前後で同じ座標に留まった。844→480pxの高さ縮小でも下部の位置を保持。英語カテゴリartist cgを選ぶと`category:"artist cg"`が入力され、その式で検索画面へ遷移した。証跡はGit対象外の`test-output/search-ui-proof.jpg`。
