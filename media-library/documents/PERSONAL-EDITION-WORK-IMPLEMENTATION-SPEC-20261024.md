# 個人DB：作品情報・詳細表示・編集画面の実装引継ぎ仕様

更新：2026-10-24。対象：現行Folioの個人DBを、会議・操作試作で合意した作品構造と画面へ改修する作業。

**現在は資料化のみ。本番コード変更、実DBの移行、評価の書き込み、VPS配備は行わない。後の会話でユーザーが本番適用を指示したときに使用する。** 試作を本番として配備する指示ではない。

## 1. この資料の位置付け

- 本資料は2026-10-24までの最新合意をまとめた、個人DB改修の引継ぎの入口とする。過去の議事録・個別資料・試作との食い違いは、ここに明示した最新の訂正を優先する。
- **個人DBは主リンクのページ数・発売日・公開日を表示する。ソース採用優先度・優先順位内の最大ページ数／最古日付は使わない。** 採用優先度は共用カタログ側の別仕様。
- **詳細画面の詳細情報は常時表示。編集画面は各セクションを初期展開し、利用者が個別に折りたためる。** 以前の「詳細画面も折りたたむ」「編集04は折りたたみ操作なし」は更新された。
- **AI区分の補足・根拠を自由入力する欄は不要。** 試作の欄をそのまま本番へ持ち込まない。
- 明確な製品上の合意と、実装を成立させるための技術上の推奨を区別する。第12節に残る設計事項を列挙する。会議全体・公開版全体の仕様確定を意味しない。

関連資料：[リンク別情報](PERSONAL-EDITION-LINK-METADATA-PLAN.md)、[分類・rating0移行](PERSONAL-EDITION-CATEGORY-RATING0-PLAN.md)、[原作・シリーズ移行](PERSONAL-EDITION-ORIGINAL-SERIES-PLAN.md)、[キャラクター対応](PERSONAL-EDITION-CHARACTER-ORIGINAL-PLAN.md)、[AI区分](PERSONAL-EDITION-AI-CLASSIFICATION-NOTES.md)、[試作と検証範囲](WORK-UI-PROTOTYPE.md)。

## 2. 対象範囲と維持する機能

今回のまとまりは、作品情報の保存構造・移行、詳細表示・詳細編集、既存取り込みとの接続。共用カタログ、公開投票、ユーザー認証の刷新、公式リンク自動探索を同時実装するものではない。

個人DBへの自由な登録を維持する。公開カタログへ掲載できないことを理由に個人保存を失敗させない。既存の作品ID・メタデータID・リンクID・URL比較／重複処理・ゴミ箱・統合・評価・マーク・レビュー・ブックマーク名履歴を保護する。今回の変更を理由に同タイトル作品を拒否する旧仕様へ戻さない。

既存の検索・保存検索・一括処理・メタデータ編集・画像RAM中継・表紙手動変更・ブックマークレット・OS共有・インポート各画面・バックアップ入出力も影響確認の対象とする。新画面を作ってそれ以外の経路を黙って欠落させない。

英語・日本語UIを維持し、新しい文言も両方用意する。色は既存の黒・オレンジを基本とする。細かな余白等は実機で調整できるが、下記の操作契約は変えない。

## 3. 保存する情報と責務

以下は論理モデル。DBの具体的なテーブル名・列名を既存実装と確認せず確定したSQLとして扱わない。

| 単位 | 保持する情報 |
| --- | --- |
| 個人作品 | タイトル、手動表紙URL、作品形式、刊行区分、創作区分、作者、サークル、タグ、原作、キャラクター、シリーズ、年齢区分、AI区分、個人評価・レビュー・マーク、既存の登録／更新／閲覧情報 |
| ソースリンク | URL、URL比較キー等の既存識別情報、自由入力ラベル、表示順、主リンク指定、リンクの役割、複数言語、ページ数、日付の一覧 |
| 収録関係 | 子作品ID、任意の収録先作品ID、収録先名、任意の収録先URL。収録先IDとURLは同時保持可能 |
| キャラクター辞典 | 原作との対応、自動／手動の由来、明示的に自動接続を禁止した組合せ |

- タイトル・作者・タグなどをリンク単位へ全面移転しない。作品は利用者が整理する個人エントリのまま。
- 内部の取得元サイト識別子はURL等から判定する。自由入力ラベルとは独立させる。ラベルを「フルカラー版」にしてもDLsiteが別サイトへ変わる扱いにしない。
- 個人DBには採用優先度の入力・設定・確認ダイアログを設けない。共用側の将来の優先表とは分離する。
- 作品形式：漫画／CG・イラスト／その他。刊行区分：同人／商業。創作区分：一次創作／二次創作。いずれも未設定を許容し、創作区分と刊行区分を混同しない。
- 年齢区分は任意の詳細情報で初期値は成人向け。取得元の明示情報と手動値、単なる初期値を同一の確認済み情報とみなさない。
- CG枚数の専用欄、基本枚数と差分込み枚数、説明文からの枚数推定は追加しない。

### 3.1 主リンクを使う個人DBの概要表示

| 項目 | 最新ルール |
| --- | --- |
| ページ数 | 主リンクに保存した値。副リンクの最大値やサイト優先度で置き換えない |
| 発売日 | 主リンクに保存した発売日。副リンクから補完しない |
| 公開日 | 主リンクに保存した公開日。副リンクから補完しない |
| 一つの日付表示にまとめる場合 | 主リンクの発売日を優先、なければ同リンクの公開日。種別を表示する。その他の日付は使わない |
| 提供言語 | 全リンクの言語の和集合。重複を除き、主リンクの言語だけに絞らない |
| 表示画像 | 個人作品に保存された表紙URL。今回の訂正で主リンクの画像へ自動上書きする規則は追加しない |

主リンクの値がなければ未設定として扱い、他リンクの値を作品にコピーしない。主リンク変更で概要表示は再計算するが、各リンクの保存値は移動・消去しない。作品側に概要のキャッシュを置く実装なら、主リンク変更・値変更・復元時に更新し、別の正本にしない。

過去に全本編候補へ適用していた役割フィルター・最大値選択を個人概要へ流用しない。主リンクの役割を理由に別の本編リンクへ差し替えず、主リンクに登録した値を表示する。日付種別の「その他」を概要へ採用しない規則は維持する。

### 3.2 リンク別言語・ページ数・日付

- 言語は配列／多対多の構造。インポーター共通変換、保存、API応答、再編集、検索まで複数値を保持する。先頭だけ選ぶ処理を残さない。
- 空配列／未設定と「文字なし」を区別する。サイトのUI言語や作者の国籍から作品言語を推定しない。
- ページ数は未設定または0以上の整数。0を未設定へ暗黙変換しない。CG枚数と同一視しない。
- リンク役割は本編／サンプル／その他・未確認。別版名はラベルに記録し、役割へ混在させない。
- 日付種別は発売日／公開日／その他。その他には任意の意味を入力できる。日付種別のその他とリンク役割のその他は別項目。
- 日付は年・年月・年月日を許容し、入力した精度を保持する。存在しない日付はエラー。年のみを1月1日として確定保存しない。
- 通常は日付一行から始め、「日付を追加」で種別と値を増やす。空の行を勝手な日付として保存しない。その他の日付を概要の発売日／公開日として表示しない。
- 副リンクを含め、全欄を手動入力させる必要はない。取得できた情報・利用者が入力した情報だけ保持すればよい。

### 3.3 収録関係と逆方向表示

- 子作品から、Folio内エントリと名前・外部URLを指定できる。収録先が未登録でも保存可能。未登録参照のために通常作品を自動作成しない。
- エントリ接続と外部URLは排他的にしない。一つの収録先作品が複数ソースを持てる。
- 詳細の収録先名はエントリ接続があればFolio内へ、外部URLは外部サイトへ開く。収録先URLを子作品の本編ソースへ自動追加しない。
- 収録先側の詳細画面下部には、そのエントリを収録先として指定している子作品を「収録作品」として一覧表示し、各詳細へ移動できる。
- 逆方向は明示したエントリIDへの接続から求める。タイトル一致・URL文字列の類似だけで関係を自動確定しない。名前とURLだけの参照は自動で逆表示へ混ぜない。
- 技術上の推奨：逆方向を二重保存せず直接の関係から取得する。所有者の範囲を検証し、他人の個人作品を参照させない。自己参照・重複関係は入力エラーにする。循環・ゴミ箱・参照先削除の最終仕様は第12節。

## 4. 詳細表示画面

### 4.1 画面の基本配置

1. ライブラリへ戻る操作。検索条件・並び順・スクロール復帰は現行の挙動を維持。
2. 表紙、タイトル、分類、作者・サークル、個人記録、タグ等の主要メタデータ。
3. ソースリンク一覧。
4. 年齢・AI区分・収録先等の詳細情報を画面下部へまとめる。
5. 収録先として参照されている場合は下部に「収録作品」欄。

**詳細情報全体を折りたたむボタンは置かない。** 必要な情報へスクロールして読める構成とする。空の任意情報を大量の未設定欄として強調しない。

表紙は縦長に切り抜かず、元の縦横比を保って表示領域の幅へ合わせる。表紙タップで主リンクへ。主リンクなしの場合は不正なリンクを作らない。

右上は現行のコンパクトな共有・ゴミ箱・鉛筆アイコンを維持。削除は赤、確認後にゴミ箱移動。**試作にある「作品詳細／編集」切替タブは不要。** 鉛筆を編集入口とする。編集から戻る操作は保存・キャンセル等で提供する。

### 4.2 メタデータと個人記録

- 二次創作では原作とキャラクターを主要メタデータとして表示。一次創作・未設定では下部の詳細情報側へ。分類変更で登録情報を消さない。
- 原作・題材とシリーズは別見出し。作者・サークルも両方維持する。
- タグの女性／男性属性は現行の色と♀／♂で表示。属性なしには性別記号・「無属性」の文字を追加しない。
- rating0を総合評価として先頭に表示。独自評価rating1以降も番号・名称・記号を維持する。未評価と星0を混同しない。
- マークは主要記録として押し出さず、現行の控えめな展開型を維持。詳細画面の切替は即保存。詳細情報の常時表示という変更はマークの展開操作を廃止する意味ではない。
- レビューの改行、メタデータからの検索遷移、ページ名「作品タイトル - Folio」を維持。

### 4.3 ソースリンク行

- ラベル、主リンクの印、役割、言語、ページ数、主な日付を閉じた状態でも確認できる。
- **行本体は外部リンクを開く。右端の矢印だけでURL全文・追加の日付等の補足を開閉する。** ラベルを押して行の開閉になる実装に戻さない。
- 外部リンクと開閉ボタンを独立した要素にする。補足ボタンには開閉状態と対象を支援技術へ伝える属性を付ける。キーボードでもそれぞれ操作可能にする。
- 「詳細情報全体は折りたたまない」と「リンクごとの補足は矢印で開閉できる」は両立する。

## 5. 編集画面

### 5.1 セクションと初期状態

| セクション | 内容 |
| --- | --- |
| 01 基本情報 | タイトル、作品形式、刊行区分、創作区分、作者、サークル、タグ。二次創作なら原作・キャラクターもここ |
| 02 ソースリンク | 主リンク選択、各リンクのURLと自由入力ラベル、リンク別情報 |
| 03 個人記録 | rating0、独自評価、マーク、レビュー |
| 04 詳細情報 | 一次創作・未設定の原作／キャラクター、シリーズ、年齢、AI区分、収録先 |

表紙のプレビュー・画像URL編集も維持する。PCでは試作の左側配置、スマホでは上部配置を出発点とし、縦横比を保つ。

- 各セクションは初期状態で開く。利用者が見出しから個別に折りたためるようにし、入力済み領域を畳んで作業できる。
- 閉じても入力値を消さず、タイトル・リンク件数・記録済み項目等の短い要約を見せる。
- 日英切替、タグ追加、リンク追加、評価選択等による再描画で未保存値と開閉状態を失わない。
- 折りたたみ状態の再訪時の記憶は第12節。少なくとも同じ編集作業内では維持する。
- 二次創作への変更で原作・キャラクターを基本へ移し、戻すと詳細へ移す。手動で選んだ創作区分をインポートで勝手に変えない。原作未取得だけで一次創作と判定しない。

### 5.2 ソースリンクの編集

- URLとラベルを別の入力欄として置き、ラベルは任意のサイト名・版名を自由入力できる。取得元サイトの固定選択欄は置かない。
- **「ソースリンクを追加」は最後のリンクの下に置く。** ゼロ件の場合も同じ一覧末尾の位置に表示する。追加後は新しいURL欄へフォーカスする。
- リンク固有の詳細は必要なときだけ展開できる配置を許容するが、URL・ラベル・主リンク指定は通常表示する。入力エラーがあれば開く。
- 言語は複数選択。ページ数・役割・日付の入力方式は第3節。主リンク変更はラジオ等で一つを明確に選べるようにする。
- 今回の整理で既存のメタデータ再取得ボタン・既存作品への統合入口を削除しない。これらの配置は既存機能との接続として確認する。

### 5.3 保存とキーボード

- 編集中は通常の検索／ランダム／新規追加等のユーティリティバーを隠す。
- 代わりに保存・キャンセルのバーを画面下部へ固定。PC・スマホとも長いページを戻らず保存できる。編集用固定バーに削除ボタンは追加しない。
- ページ末尾にも保存・キャンセルを残す。固定バーと同じ処理を呼び、二種類の保存規則を作らない。
- ソフトウェアキーボード表示時は固定バーを隠し、入力領域を覆わない。閉じると復帰。セーフエリアとバーの高さ分の末尾余白を確保する。
- キーボードの判定方法はブラウザ差を考慮する。試作のVisualViewport・150px差分・フォーカス判定は試作上の実装であり、実機確認なしに本番の正解とみなさない。
- 個人記録も含め、編集画面の変更は作品の保存時に確定する。詳細画面のマーク即保存と混同しない。

### 5.4 未保存での移動

試作内・本番アプリ内のページ移動では、変更がある場合に以下を選べる。

| 操作 | 動作 |
| --- | --- |
| 保存して移動 | 入力検証→保存成功→最初に指定した移動先へ。詳細への強制遷移にしない |
| 破棄して移動 | 作品の未保存変更を破棄して指定先へ |
| 編集を続ける | 編集状態・入力値・位置を維持し、移動しない |

対象には戻る操作、別作品、ライブラリ、新規追加、内部ハッシュ／履歴による移動を含む。検証エラー時は該当セクションとリンク詳細を展開して該当入力へ移動する。保存失敗時は移動せず入力を保持し、再試行可能にする。

ブラウザの再読み込み・タブを閉じる操作には、ブラウザ標準の未保存確認を使う。そこで独自の3択が必ず出せると約束しない。保存処理中の二重送信、遅い応答が別作品の画面を上書きする問題も防ぐ。

メタデータ辞典そのものの編集・統合は、作品の未保存編集と異なる操作である。作品をキャンセルしても既に確定した辞典の編集まで自動で巻き戻す仕様を追加しない。

## 6. AI区分

保持する4区分は、AI生成／AI一部利用／非AI生成（取得元基準）／不明・記載なし。取得元の明示情報を対応付け、ラベル不在を不使用と判定しない。画像解析等で利用程度を推測しない。

**「取得元の区分・根拠」「AI補足」等の自由入力欄は設けない。** 詳細表示にも試作の自由文をそのまま追加しない。これはAI区分の選択自体を廃止する意味ではない。

将来インポーターが取得した元区分・URLを内部保存し、必要に応じ確認できる方向は維持するが、ユーザーの補足入力を必須にしない。複数ソースで異なる場合の自動上書き規則は未決。個人DBの主リンク表示ルールをAI区分にまで勝手に一般化しない。

## 7. 取り込み・保存経路への反映

- リンク別情報の取得結果を、その取得対象のリンクに保存する。他のリンクや作品の表示値へ無条件複製しない。
- 既存値と取得値が同じなら変更・比較確認を増やさない。取得失敗・空の結果で既存値を消さない。
- 作品の既存メタデータはF-013の比較を維持。複数選択項目は上書き／マージ／そのまま、空欄は補完。取得データが空なら維持する。
- 言語も複数値として比較・保存する。取り込み元の配列を単一文字列や最初の値へ変換しない。UIの比較方法は既存の複数選択項目の方式を基本とし、具体形は実装時に確認する。
- 通常の登録済みURLを共有・ブックマークレットから開いた場合、既存詳細へ進む挙動を維持する。明示的な再取り込みだけが比較更新へ進む。
- 全く同じURL、ページ違い、ゴミ箱上のリンク、統合済み元リンク等の既存処理を別の重複規則に置き換えない。旧作品タイトルの履歴を使って候補を暴走させない。
- 個人タイトル・表紙・ラベルは利用者の保存値を尊重する。共用側の採用優先度を使って書き換えない。
- Hitomi等で原作・パロディとして取得する情報は新しい原作欄へ対応させる。既存seriesへの取り込みをそのまま残さない。新規データの名称が英語か日本語かで原作／シリーズを決めない。

## 8. 既存データの移行

本番実行前にバックアップと復元方法を確認し、読み取りの移行プレビューを作る。実装時の実DBを確認する前に「該当なし」「3軸はこのID」「リンクなしはゼロ」と断言しない。

### 8.1 カテゴリと原作／シリーズ

| 旧値・対象 | 移行 |
| --- | --- |
| manga | 漫画＋商業 |
| doujinshi | 漫画＋同人 |
| artist cg / image set | CG・イラスト。旧値だけから刊行区分は断定しない |
| game cg | その他 |
| 英語が主表記の既存シリーズ | 原作へ移動 |
| 日本語主表記のブルーアーカイブ・グラブル | 対象IDを特定して原作へ移動 |
| その他の日本語主表記の既存シリーズ | シリーズとして維持 |

原作／シリーズの振り分けは今回の既存データに限る。別名に英語があるだけで判定しない。混在・記号のみ等は一覧確認し、推測で一括移動しない。IDの維持・対応表を用意し、別名と作品への関連を失わない。既存の未設定値は勝手にその他へ変換しない。

### 8.2 ページ数と言語

- 現在の作品側ページ数と言語を現在の主リンクへ移す。既存ページ数の出所を推定して振り分け直さない。副リンクへ複製しない。
- 作品ID・主リンクがない等の想定外データがあれば、値を破棄する代わりに移行を止めて報告する。新しいリンクなし作品補助機能を勝手に増やさない。
- 過去に失われた2番目以降の言語は、現行の一値だけから復元できない。全件再取得を今回の移行に無断で含めない。
- 既存値と新しいリンク情報の両方が既にあるDBへの再実行は衝突検出し、新しい手動編集を旧値で戻さない。

### 8.3 rating0の一回の初期値生成

固定の星1〜5総合評価をnumber=0で追加。rating1以降の番号は変更しない。0点を未評価として保存しない。

1. rating1（ストーリー）またはrating2（淫靡さ）が5なら、他が未評価でもrating0=5。
2. それ以外で指定の既存3軸がすべて評価済みなら `ceil((rating1 + rating2 + 3軸目) / 3)`。
3. それ以外は総合未評価。未評価を0として計算しない。

3軸すべて5段階の場合、特例なしでは合計3→1、4〜6→2、7〜9→3、10〜12→4、13〜15→5。3軸目だけが5でも無条件5にはしない。

実際の3軸のID・番号・最大値を確認する。想定外の段階数、追加軸、既存rating0の衝突は、独断で正規化・再採番しない。既に利用者が入力したrating0を移行の再実行で上書きしない。移行後は独立した評価として変更し、独自評価から自動再計算し続けない。

### 8.4 キャラクターと原作

- 保存する作品の原作が一つなら、付与されたキャラクターへ自動接続。原作IDとキャラクターIDで扱う。
- 原作が複数なら全組合せを自動作成せず、既知の対応を維持し未判明分は手動選択。原作なしなら新規接続しない。
- 辞典で明示解除した組合せは別作品・再取り込みで復活させない。手動再接続は可能。
- 辞典の接続解除は、作品の原作・キャラクター自体を外す操作と別。接続の由来を自動／手動で確認できるようにする。
- 既存データの一回の自動対応生成、同名キャラクターの整理、根拠作品削除時の扱いは第12節。既存キャラクターを作品ごとに勝手に分割しない。

## 9. バックエンド・互換への引継ぎ

### 読み取り・書き込み

- 作品の取得・保存APIで分類3項目、原作とシリーズ、収録先、リンク別の言語配列・ページ数・日付一覧を往復できるようにする。
- 詳細取得では逆方向の収録作品を取得できる経路を用意する。保存側が逆向き一覧を正本として書き戻す設計にしない。
- 未設定、空配列、削除要求、取得元の空結果を区別する。旧クライアントから新規項目が送られないだけで新項目を削除しない。
- 主リンク指定とリンク情報・関係・作品本体の更新は不整合な中間状態を残さない。リンクなし／主リンク複数の扱いは現行の不変条件と確認する。
- バックアップの形式バージョンを管理し、旧バックアップを読み込む経路と、新項目を含む往復を確認する。作品ID・既存外部共有トークンの維持に注意する。

### 検索・共有・統合

- タイトル、作者、原作、シリーズ、キャラクター、旧カテゴリの検索と保存検索への影響を洗い出す。構文・互換の決定は次の議題。既存OR優先、NOT、引用、ratingN等を無断で変えない。
- 概要は主リンク、言語表示は和集合という表示規則を、そのまま検索の条件へ置き換えない。同じリンクで成立させる条件は検索契約として別に明文化する。
- 既存の固定共有は個人DBの共有スナップショットで、共用カタログとは別。今回の移行で過去のスナップショットを書き換えない。
- 新規スナップショットにどの追加項目を含めるかは第12節。既存の共有解除・リンクカード・NSFW露出への対策を維持する。
- 作品統合、リンク追加、ゴミ箱、復元、完全削除、一括編集でも新しい情報を不意に落とさない。統合先と元で新しい原作・分類・日付等が異なる場合に、既存の比較UIへどこまで追加するかを実装時に確認する。

## 12. 未確定の細部・次の会議

合意済みの基本方針を再度未決へ戻さず、以下を分けて扱う。

### 製品仕様として残ること

1. 検索構文・保存検索の移行：原作／シリーズ、分類の分離、リンク言語・ページ数・日付と主リンク条件の指定。表示と検索範囲の違い。
2. 主リンク内の同種日付が複数ある場合の概要・並び替え、不完全日付の比較、予定日。
3. AI区分の複数ソース競合・手動変更の優先。自由入力の補足欄を設けないこと自体は確定。
4. 収録関係の循環、参照先のゴミ箱・削除・統合、順序。キャラクター対応の既存データへの生成範囲・根拠作品削除後の扱い。
5. 新規の個人固定共有へ含める新項目。過去の共有を自動書換えしないことは確定。
6. 分類・言語等の新フィールドを一括編集・統合時の比較へどう載せるか、旧バックアップの不完全な項目を復元する際の既存値との衝突。

### 実装時に判断・実機調整できること

具体的なスキーマ・API形、移行番号、保存トランザクション、索引、レイアウト余白、入力欄の文言、折りたたみ状態の端末内保存方法、キーボードの検出方法。記憶を実装する場合も、所有者と画面を分け、初回の初期展開とエラー表示を妨げない。
