# momon-ga インポーター — 実現性調査

調査日：2026-10-13。調査のみ承認済み。インポーターの実装・稼働DBへの登録は行っていない。

## 結論

現時点で、作品ページのHTMLからメタデータと表紙URLを取得する方式は実装可能と判断する。
同人誌・商業誌の2ページで、ログインやAPIキーなしのHTTPS取得が成功した。
商業誌の表紙と2ページ目は画像応答も確認でき、既存のRAM内画像中継へ拡張する見込みがある。
全作品・大量取込・スマホ実ブラウザー表示・継続的な取得可否は未検証。

## 調査方法・参照

- [サイトのトップページ](https://momon-ga.com/)から作品URLと分類を確認。
- 同人誌1件と[商業誌1件](https://momon-ga.com/magazine/mo4231061/)を通常のHTTPS GETで読み取り、HTML構造を確認。
- サイト自身のスクリプトを読み取ったが実行していない。外部の広告スクリプトは取得・実行していない。
- 商業誌の画像2件は先頭64バイトとHTTPヘッダーだけをメモリ内で読み取り、ファイル保存・画像表示は行っていない。
- [マイリストの説明](https://momon-ga.com/mylist/)とHTML内の保存コードを確認。
- robots.txtは確認時にHTTP 200・本文空だった。公開APIの文書や取得レートの保証は今回確認できていない。

調査スクリプトはGit対象外の `test-output/probe_momonga.py` と `probe_momonga_structure.py`。HTMLと画像は永続保存していない。

## 確認できたデータと解析方法

| 情報 | 取得元 | Folioへの対応案 |
|---|---|---|
| タイトル | 本文のh1、history要素のdata-title | 表示中の元タイトルをそのまま使用 |
| 同人誌／商業誌 | #post-category | 現行カテゴリの対応を仕様決定 |
| 作者 | #post-tag内の/cartoonist/リンク | author |
| サークル | 同/group/リンク | circle |
| パロディ | 同/parody/リンク | series |
| キャラクター | 同/character/リンク | character |
| 内容タグ | 同/tag/リンク | tag（属性なし） |
| ページ数 | #post-number | pages |
| 表紙 | historyのdata-thumb、本文画像の1ページ目 | cover_url |
| 本文画像一覧 | #post-hentai内のimg src | ページ指定対応時のURL候補 |
| 正規URL | canonical、data-url | ソースURL検証・識別の補助 |

メニュー・関連作品にも同じ種類のリンクや画像があるため、ページ全体のリンクやimgを無条件に集めない。
商業誌の全imgは545件だったが本文は521件で、#post-numberの521と一致した。同人誌は本文18ページ。
HTMLのtitleにはサイト名や補助表記が付くため、h1を優先する。
タグリンクのURLスラッグを名前へ変換せず、リンクの表示文字列を読み取る。
作者名などの `a | b` は別名表記の可能性がある。別人へ自動分割しない方針を推奨し、既存の別名照合との対応を決める必要がある。

## URLと作品ID

確認した作品URLは `/fanzine/mo数字/` と `/magazine/mo数字/`。
ページ内のWordPress投稿IDとURLのmo番号は異なる。例：商業誌の投稿ID373009、mo番号4231061。
数字が他サイトのIDに似ていても、それだけでHitomi／nhentaiと同じ作品と断定しない。
既存の同名・作者候補確認、副リンク追加、完全一致URLスキップの仕組みを利用する案。

途中ページを表す標準リンク形式は今回確認できなかった。本文imgにページ別idは見つからず、ページ番号のアンカーリンクも見つからなかった。
location.hashのコードはヘッダーを隠す処理で、ページ番号の解釈とは確認できない。
したがって `#2` などを勝手に2ページ目と解釈しない。途中ページURL対応にはユーザーが使っている実例または追加調査が必要。
画像URL自体を渡された場合の逆引きも未承認・未検証。初期版は作品ページURLから1ページ目を表紙にする案。

## 画像

確認できた画像URLは `https://z2.momon-ga.me/galleries/数字/ページ.webp`。
商業誌の1・2ページ目に、Refererなし／作品ページをRefererとする両条件でHTTP 200、Content-Type image/webp、RIFF/WEBPの先頭バイトを確認。
サイズは約139KBと383KB。ブラウザーのCSP・表示挙動・他画像サーバー・全作品の可否は未検証。

直接URL表示ができる可能性はあるが、Folioでは現在の方針に合わせてRAM内中継を追加する案。
DBにURLだけを保存し、画像データはメモリ内で上限・期限付き管理とする。
URLを数字だけで組み立てず、HTMLに記載された実URLを採用する。観測したホスト・パスを検証し、任意URL中継にはしない。

## アクセス上の制約

Python既定のUser-Agentでは商業誌ページが403、通常のブラウザー風User-Agentでは200になった。
HTML取得に実行ブラウザーは必須ではなかったが、取得側のヘッダーと拒否応答への処理が必要。
サイト変更、403、429、タイムアウトに備え、低頻度の直列取得と一時停止・再試行を設ける。
アクセス制限の回避やCAPTCHA突破を前提にしない。HTMLを安全に解析し、広告・JavaScriptを実行しない。

## マイリスト

サイト自身がブラウザー機能で保存すると説明し、コードはlocalStorageの `localFavorites` を使用していた。
nhentai FavoritesのようにアカウントAPIキーでサーバーから一覧を取得する仕組みは今回確認できていない。
もしマイリスト取込も必要なら、そのブラウザー上でURL一覧を明示的に書き出す仕組みを別途設計する。通常のブックマークHTML取込は既存経路へ追加できる見込み。

## Folio実装時の変更箇所（提案）

- momon-ga専用のURL検証・上限付きHTML取得・本文限定解析アダプターを追加。
- importer.source_identity/import_url、ブックマーク取込の対応URL、共有・ブックマークレットの対応サイトを拡張。
- 現行の副リンクラベルにHitomi／nhentaiを決め打ちしている部分を拡張。
- 無属性タグの取込へ既存の「無属性／ライブラリ内の使用頻度」方式と別名衝突処理を適用する案。現在はnhentai条件に結びついた処理もあるため共通化が必要。
- 正規化URL・同じ作品の別ページ通知・既存作品への明示的再取込・同一作品候補の確認を既存仕様へ合わせる。
- 画像中継のホスト／パス許可と取得を追加。現在の画像リサイズに関する未コミット変更は別作業として維持する。
- 個別取込、ブックマーク、共有、副リンク追加、再取込、画像、拒否・失敗応答を隔離環境で検証。

## 実装前に決めること

1. 初期対応範囲は作品ページURLの個別・ブックマーク・共有取込でよいか。マイリスト書き出しは別機能とするか。
2. 性別情報のないタグへnhentaiと同じ無属性／使用頻度方式を適用するか。
3. 表紙は原則1ページ目でよいか。途中ページ指定は実例確認後に追加するか。
4. 作者などの ` | ` 表記を元の文字列として扱うか、確認済みの別名として扱うか。

本調査の取得成功は、全件対応や将来のサイト仕様を保証するものではない。公開版共有カタログへ掲載するソース方針とは別の、個人版インポーターの調査である。
