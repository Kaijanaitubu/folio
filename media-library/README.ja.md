# Folio — パーソナルメディアライブラリ

[English](README.md) | [日本語](README.ja.md)

Personal Media Database Requirements v2.0をもとに作成した、PC上で動作するWebアプリです。Pythonの標準ライブラリ、SQLite、ブラウザのJavaScriptを使用します。追加パッケージのインストール、有料ホスティング、Nodeによるビルド、外部アカウントは不要です。

## このPCで起動する

このフォルダでPowerShellを開き、次のコマンドを実行します。

```powershell
.\start.ps1
```

ブラウザで **http://localhost:8765** を開きます。利用中はサーバーとターミナルを起動したままにしてください。終了するにはCtrl+Cを押します。PowerShellがスクリプトをブロックする場合は、実行ポリシーを変更せず、このPCにあるPythonを直接起動できます。

```powershell
& "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" server.py
```

別のPCでは、Python 3.11以降をインストールして実行します。

```powershell
py -3 server.py
```

起動スクリプトは、このPCにある同梱Python、Pythonランチャー、`python`の順に利用可能な実行環境を探します。ポートと接続を受け付けるアドレスを指定することもできます。

```powershell
.\start.ps1 -Port 8765 -ListenAddress 0.0.0.0
```

`127.0.0.1`を指定すると、このPCからのみ接続できます。同じデータベースを使うサーバーを2つ同時に起動することは想定していません。別のサーバーを起動する前に、既存のサーバーを停止してください。

ターミナルを開いたままにせず使うには、`./run-background.ps1`を実行します。非表示でサーバーが起動し、プロセスIDを`data/server.pid`に記録します。`./stop.ps1`は、そのサーバーだけを停止します。ログは`data/server.log`と`data/server-error.log`に保存されます。この起動スクリプト自体は自動起動設定を変更しません。Windowsへのサインイン後に自動起動するには、次の設定を行ってください。通常のターミナルで起動したサーバーは、バックグラウンド起動の前にCtrl+Cで停止します。

## Windowsでの自動起動

`./autostart.ps1`を一度実行すると、現在のWindowsユーザーに対して自動起動が設定されます。ユーザーのスタートアップフォルダにショートカットを1つ作成し、サインイン時に既存のデータベースとポート8765を使ってサーバーを非表示で起動します。ブラウザは開きません。起動済みかどうかを確認するため、二重起動を防げます。自動起動のタイミングは、Windowsのログイン画面が出る前ではなく、サインイン後です。アプリのフォルダとPythonの実行環境は同じ場所に置いてください。移動した場合は、設定スクリプトを再実行します。

`./autostart.ps1 -Disable`でショートカットを削除できます。起動中のサーバーは停止しないため、停止には`./stop.ps1`を使ってください。既存のPowerShell実行ポリシーに従い、Windows Script Host/VBScriptを利用します。管理されたPCでは、これらが無効化されていると起動できない場合があります。システムの実行ポリシー、ファイアウォール、ルーターの設定は変更しません。

## スマートフォンから接続する

1. スマートフォンをPCと同じWi-FiまたはLANに接続します。
2. Windowsのネットワーク設定または`ipconfig`で、PCの有効なLAN側IPv4アドレスを確認します。
3. スマートフォンのブラウザで`http://PCのLAN側IPアドレス:8765`を開きます。
4. Windowsがファイアウォールの許可を求めたら、Pythonサーバーへの接続は**プライベートネットワークのみ**許可します。規則を追加する場合は、プライベートネットワークのローカルサブネットからのTCPポート8765への受信接続に限定してください。アプリがファイアウォールやルーターを変更することはありません。

利用中はPCの電源を入れ、スリープさせないでください。このバージョンは信頼できるLANでの利用向けで、アカウント認証はありません。ポート転送やインターネットへの公開は行わないでください。すべてのブラウザが同じサーバーのデータベースを見るため、端末間の同期設定は不要です。VPNやWi-Fiの端末間通信を遮断する設定によって、LAN接続ができない場合があります。

## 主な機能

- 画面サイズに対応するギャラリー、作品詳細、手動登録・編集、完全削除前の確認。黒とオレンジのダークテーマが標準で、設定からライトテーマに変更できます。
- 各画面で利用できる検索入力欄。Enterまたは虫眼鏡ボタンで検索結果を表示します。追加とランダムのボタンはアイコンのみで、狭いスマートフォン画面でも表示します。スマートフォンでは検索欄へのフォーカス時にバーを上部へ移動し、別の欄の編集中はキーボードと重ならないよう一時的に非表示にします。保存・削除ボタンは編集フォームの下に配置します。
- 複数のソースURLと1つのプライマリリンク。画像URL、メモリ内だけで動作するHitomiサムネイル中継、画像を取得できない場合の代替表示。
- タグ・作者・サークル・シリーズ・キャラクターの一覧。名前からの絞り込み検索、優先表示する別名、関連作品数、共通情報の編集、明示的な統合・削除、名前・作品数・追加順での並べ替えとページ分割。従来の性別フィルターは並べ替え選択に置き換えています。
- 自由に追加できる評価軸。固定の番号付き検索キー、2〜10段階の評価、10種類の記号、ギャラリー表示の設定、評価軸ごとの並べ替え。
- Unicodeに対応するサーバー側検索。NOT → OR → ANDの優先順位、入力候補、ページ分割、シードで再現できるシャッフル、検索結果全体から偏りなく選ぶランダム表示。
- Hitomiのメタデータインポート。空欄の補完、複数値への追加、競合する値の明示的な置き換え、タイトル重複時の拒否。
- ブックマークHTMLのフォルダ・項目プレビュー。進行状況、キャンセル、再試行、重複レポート、サーバー再起動後の復旧に対応したインポート処理。
- 英語・日本語の切り替え。選択した言語はブラウザごとに記憶します。
- 1日ごとの自動データベースバックアップ。7世代を保持し、設定画面から手動バックアップもできます。

## 検索例

ライブラリの並べ替え順はブラウザごとに記憶され、再読み込みやホームへの移動後も維持されます。保存したURLや検索URLに並べ替え順が明示されている場合は、そちらを優先します。指定された評価軸が削除されていた場合は、追加が新しい順に戻ります。別の画面から検索した場合も、記憶した並べ替え順を使います。この設定は端末間では同期しません。

```text
author:"Alice Smith"/author:Bob rating1:>=4
female:example -tag:another
title:"A/B" pages:>=50
review:"my notes"
bought:yes
```

最初の例は「（作者がAlice SmithまたはBob）かつrating1が4以上」を意味します。メタデータのフィールド検索は名前または別名の完全一致です。フィールドを指定しない単語、`title:`、`review:`は部分一致で検索します。レビューはフィールド指定のない検索には含めません。`tag:`はすべての性別属性を対象とし、`female:`、`male:`、`neutral:`は属性を限定します。`rating:`は使えません。`rating1:`のような番号付き評価軸を指定してください。引用符で囲む値では`\"`と`\\`のエスケープを使用できます。括弧には対応していません。検索式に誤りがある場合は、無視せずエラーを表示します。

タイトルは前後の空白を除去したうえで、大文字・小文字を区別して完全一致で比較します。タグの同一性は元の名前とfemale/male/neutralの組み合わせで判断します。性別未設定と無性別は、どちらもneutralとして扱います。別名が一致しても、メタデータを自動で統合することはありません。

メタデータの編集画面で別名を追加し、**優先表示名（Primary display name）**を選択できます。作品、メタデータ一覧、選択欄、検索候補にその名前を表示します。元の名前は残り、両方の名前で検索できます。同じメタデータを利用するすべてのブラウザに反映されます。無属性タグをタップした場合は、全属性を検索する`tag:`ではなく、`neutral:`を使います。

名前の並べ替えはアルファベット順とかな順を組み合わせます。並べ替えのためだけに、文字幅・大文字小文字・かなを正規化します。漢字の名前は必要に応じて**並べ替え用の読み（Sort reading）**をかなで入力できます。未入力の場合、読みを自動で推測しません。新しいメタデータには追加日時を記録します。既存の古いレコードは日時不明として元の追加順を使い、古い順では日時のあるレコードより前に表示します。編集してもこの順序は変わりません。該当する全項目をサーバーで並べ替えた後、100件ずつページに分けます。

## インポート

### HitomiのページからFolioを開く

設定画面の**「HitomiからFolioを開く」**で、使う端末から接続できるFolioのアドレスを指定します。スマートフォンでは、localhostではなくPCのLANアドレスでFolioを開いて設定してください。生成した「ブックマークのURL」をコピーし、ブラウザに作った**「Folio」**というブックマークのURL欄に貼り付けます。PCではFolioリンクをブックマークバーにドラッグする方法も使えます。

Hitomiの作品ページまたはリーダーで、このブックマークを実行します。AndroidのChromium系ブラウザでは、ブックマーク一覧から開くのではなく、アドレスバーにFolioと入力して保存済みブックマークの候補を選ぶ必要がある場合があります。Android版Braveでの実機確認は未完了です。実行できない場合は、Folio設定画面の作品URL欄にHitomiのリンクを貼り付けて「Folioで開く」を押してください。

- 同じソースリンクがあれば、作品詳細を開きます。プライマリ以外のリンクも照合し、HTTP/HTTPSやwwwの違いは同じページとして扱います。同じリンクの登録が複数あれば、作品を選びます。
- 同じHitomi作品の別ページ・別リンクがあれば、登録済みリンクを示す確認ダイアログを表示します。既存作品を開く・キャンセル・今のリンクで新規登録のいずれかを選べます。
- 未登録の作品は、メタデータを取得した新規編集画面を開きます。元のURL・クエリ・ページ番号を維持し、保存ボタンを押すまでは登録しません。取得に失敗してもリンクは残るため、再試行や手動編集ができます。
- この入口からの取得では、同一タイトルでも警告付きで編集内容を確認できます。保存前にタイトルを変更してください。保存時のタイトル重複禁止と、通常の取込・ブックマーク一括取込の重複判定は維持します。

このブックマークは現在のURLを付けてFolioへ移動するだけで、Hitomi側からライブラリを読み取ったり、ページ内容を送ったりしません。拡張機能やインターネットへのサーバー公開は不要です。PCのサーバーが起動し、同じLANから接続できる必要があります。入口は`/#/source?url=エンコードしたURL`です。登録状況の照合だけでは、外部データの取得や作品の変更は行いません。

導線の処理は、このフォルダで`node test_source_flow.mjs`を実行するとブラウザなしで検証できます（検証には別途Node.jsが必要です）。スマートフォンで保存済みブックマークを実行する確認は別途必要です。

### 編集とブックマーク取込

作品編集画面の作者・サークル・タグ・シリーズ・キャラクターには、種類ごとの全削除ボタンがあります。確認後にその欄を空にし、保存すると反映します。編集を破棄すると保存済みの関連付けに戻ります。メタデータ辞典や他の作品には影響しません。

Hitomiの`/reader/ID.html#7`のようなリンクは、7ページ目のサムネイルを表紙に使います。見開きを指定する`#7-8`や`#7-`も、先頭の7ページ目を使用します。途中ページには大きなギャラリー用サムネイルが存在しない場合があるため、小さい`webpsmalltn`形式を使います。ページ指定が不正・範囲外の場合や、対象ページの画像ハッシュがない場合は、警告を表示して先頭ページに戻します。ページ指定のないリンクやギャラリーのリンクは先頭ページを使います。ブックマークインポートにも適用します。既存の表紙は自動変更しません。再インポート時の上書き確認で表紙を選び、保存すると置き換えられます。

1作品を取り込むには、新規登録または編集画面でURLを追加し、メタデータのインポートを実行します。保存ボタンを押すまでは作品を保存しません。複数のリンクがある場合は、取得元のリンクを選びます。一部の情報しか取得できなくても利用できます。既存の評価・レビュー・購入状態は維持します。取得したタイトルが重複する場合は、編集内容を変更せず、メタデータの適用を中止します。

まとめて取り込むには、ブラウザのブックマークをHTMLとして書き出し、ブックマークインポート画面でアップロードします。フォルダや項目を選び、処理を開始してください。成功した項目ごとに新しい作品を作成します。未対応のリンクはプレビューで除外します。タイトルの重複・欠落、別名の曖昧な一致、取得失敗は報告し、作品を勝手に統合しません。失敗・キャンセルした項目は再試行できます。ページを閉じても処理は続きます。キャンセルしても完了済みの作品は残り、すでに実行中の取得処理は完了する場合があります。

対応するソースURLには`/galleries/ID.html`、`/reader/ID.html#page`、`/category/name-ID.html`があります。保存したURLを書き換えることはありません。ほかの形式のURLも手動で保存できます。取得先は既知のソースホストに限定し、名前解決した公開IPアドレスへの接続を固定します。取得時間と応答サイズに上限を設け、リダイレクトには従いません。インポーターはソースの現在のメタデータホストからギャラリーJSONとサムネイルのルーティング表を読みます。元のページと同様に`japanese_title`を優先し、選択したページのWebPサムネイルURLを組み立てます。インポートではメタデータのみを扱い、取得元のJavaScriptを実行しません。対応するHitomi画像の表示は、次の一時的な中継機能で処理します。

## メモリ内だけで扱う画像

Hitomiの画像は、以前保存したサムネイルURLも含め、取得元サイトのリファラーを付けてFolio経由で読み込みます。サーバーがサムネイルのデータをRAMで受け取り、ブラウザに送ります。画像ファイル、SQLite、バックアップ、ログには書き込みません。ブラウザの遅延読み込みにより、表示中または表示領域付近の画像だけを読み込みます。取得できない場合は代替表示を維持します。手動で指定したその他の画像ホストは、引き続きブラウザが直接読み込みます。

一時RAMキャッシュは、最近使われていない画像から破棄するLRU方式で、画像データの合計上限は32 MiB、有効期限は5分です。同じ画像への同時リクエストは1回の取得を共有します。1枚の上限は2 MiB、中継処理の同時実行は最大4件です。送信前にRAMで応答全体を受け取り検証するため、不正な形式・サイズ超過・途中で切れた応答を部分画像としてキャッシュしません。取得やコピーに使う一時バッファは、キャッシュ上限とは別に約16 MiBを使用する場合があります。プロセスとブラウザの総メモリ使用量には、通常のアプリ動作分も加わります。

取得元への処理期限は20秒、ブラウザへの送信タイムアウトは30秒です。DNSはシステムの名前解決機能を使うため、異常な遅延がある場合、ソケットを開く前に取得期限を超えることがあります。対象は保存済み作品と対応するサムネイルホスト・パスに限ります。公開IPへの接続固定、TLS検証、リダイレクト禁止、MIMEとファイル形式の検証、同一オリジンからの画像応答により、任意のURLを取得する汎用プロキシとしての利用を防ぎます。

中継した画像には`Cache-Control: no-store, max-age=0`、`Pragma: no-cache`、`Expires: 0`を設定し、ブラウザで永続的に保存しないよう要求します。Service Workerやブラウザ内の画像データベースは使いません。Folioを再起動すると画像キャッシュは消え、有効期限切れの項目はバックグラウンド処理で削除します。保存しないという保証はアプリ自身のファイル・データベース・キャッシュへの書き込みを対象とし、OSのメモリページングやブラウザ内部の動作までは制御しません。取得元のアクセス規則が変更される場合もあります。元の調査と実装後の対応は[THUMBNAIL-INVESTIGATION.md](THUMBNAIL-INVESTIGATION.md)をご覧ください（英語）。

## データ・設定・バックアップ・復元

利用中のデータは`data/library.sqlite3`、バックアップは`backups/library-*.sqlite3`に保存します。これらはGitの管理対象外です。スキーマ移行2では、既存データを置き換えず、メタデータの表示用別名・並べ替え用の読み・追加日時を追加します。移行履歴は`migrations`テーブルに記録し、起動時の初期化は繰り返し実行しても問題ありません。今後の変更でも、ユーザーデータを初期化せず、明示的な移行処理を追加する必要があります。

環境変数は、起動前に同じターミナルで設定します。

```powershell
$env:MEDIA_DB = 'D:\Folio\library.sqlite3'
$env:MEDIA_BACKUPS = 'E:\Folio-backups'
$env:MEDIA_HOST = '0.0.0.0'
$env:MEDIA_PORT = '8765'
```

バックアップには、整合性を保つSQLiteのオンラインバックアップAPIを使用します。辞書・評価・リンク・インポート処理の状態を含み、画像そのものではなくURLを保存します。サーバー起動時と、稼働中の24時間ごとにバックアップを作成し、指定したバックアップフォルダに7世代を保持します。ディスク故障への備えには、別の物理ディスクまたは別途バックアップされる保存先が必要です。

Webサイトを起動せずにバックアップを作成するには、次のコマンドを実行します。

```powershell
py -3 server.py --backup
```

復元するには、**まずすべてのサーバーを停止**してから実行します。

```powershell
py -3 server.py --restore 'E:\Folio-backups\library-TIMESTAMP.sqlite3'
```

既存のデータベースは最初にバックアップします。復元コマンドはデータベースの整合性を検証し、SQLiteのバックアップAPIで復元して終了します。その後、通常どおりサーバーを起動してください。待機中・実行途中のインポート項目は起動時に復旧し、完了した作品と項目の書き込みは一括で確定します。このPCの同梱Pythonを使う場合は、`py -3`をその実行ファイルのフルパスに置き換えてください。

## 評価段階の変更

評価軸の編集で段階を変更し、「換算結果を確認」を選びます。変更前後の評価値と作品数を確認して「換算して保存」で確定してください。キャンセルでは保存済みデータは変わりません。最低評価は1を保ち、五捨五超入で丸め、満評価になるのは元も満評価だった作品だけです。未評価は維持します。例えば3→5段階では1/2/3が1/3/5に、5→3段階では1/2/3/4/5が1/1/2/2/3になります。段階を減らすと細かな評価の違いが失われ、段階を戻しても復元できません。元の評価に戻す可能性がある場合は、変更前に設定画面でバックアップを作成してください。別のブラウザーで評価が変わった場合は、改めてプレビューを確認する必要があります。


テストとベンチマークは`test-output/`内の独立した一時データベースを使い、実際のライブラリにテストデータを入れません。HTTPテストにはローカルのテスト用ポートで接続を待ち受ける権限が必要です。取得確認スクリプトは公開メタデータを取得しますが、作品を保存しません。記録した結果と検証上の制限は`VERIFICATION.md`をご覧ください（英語）。

## ソースコードの構成

| ファイル | 役割 |
|---|---|
| `server.py` | HTTP API、リクエストの保護、永続的なインポート処理、起動・復元 |
| `db.py` | SQLiteスキーマ、トランザクション、関連付け、メタデータ・評価の規則、バックアップ |
| `search.py` | 検索式の字句解析とパラメーター化SQLの生成 |
| `importer.py` | Hitomi用アダプターと安全なブックマークHTML解析 |
| `cover_relay.py` | 取得先を限定したサムネイル取得、上限付きRAMキャッシュ、一時画像バッファ |
| `static/app.js` | ブラウザ内の画面遷移、フォーム、ダイアログ、ギャラリー、インポート |
| `static/i18n.js` | 英語・日本語のUI文言 |
| `static/style.css`、`static/theme.css` | レスポンシブ表示、テーマ、常設ユーティリティバー |
| `test_app.py`、`test_server.py`、`test_cover_relay.py` | 基本機能、HTTP・インポート処理、画像中継・キャッシュの回帰テスト |
| `benchmark.py` | 実際の運用規模を想定したベンチマーク |

現在の所有者は`local`です。将来アカウント登録に対応できるよう、保存データには所有者の区別があります。実際のアカウント登録・認証・公開運用は、別のリリースで対応する予定です。
